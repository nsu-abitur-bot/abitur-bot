# Настройка другого вуза

Реквизиты хранятся в записи настроек экземпляра #356. Суперадминистратор
открывает «Подключения» → группу «Вуз». Env содержит только инфраструктуру.

- UNIVERSITY_PROFILE: nsu или custom.
- UNIVERSITY_SHORT_NAME / UNIVERSITY_FULL_NAME: названия вуза.
- ASSISTANT_NAME: представление помощника в системном промпте и шапке панели.
- UNIVERSITY_WEBSITE / UNIVERSITY_LOGO_URL: реквизиты сайта и логотипа.
- ADMISSIONS_EMAIL / ADMISSIONS_PHONE / ADMISSIONS_ADDRESS: контакты комиссии.

Пустые реквизиты не наследуют сайт/название НГУ в custom. Пустое имя помощника
использует нейтральное «официальный дружелюбный помощник-бот». Значения — обычный
текст, не HTML и не редактор промпта. Применяются через снимок настроек #356.
Общие реквизиты доступны авторизованным сотрудникам через GET /api/v1/university;
ключи провайдеров и прочие настройки в этот ответ не входят.

## Первое включение и совместимость

Миграция 7b4e1d9c2a60 создаёт custom для чистой БД до bootstrap, поэтому
новый стенд не получает справочник/баллы НГУ. Для имеющихся настроек либо
существующих данных сохраняется nsu; явно заданный профиль не перезаписывается.
Для давно созданной, но полностью пустой БД без настроек выберите nsu вручную,
если это стенд НГУ. При импорте старого env проверьте профиль после импорта.

На custom независимо от SEED_* блокируются справочник и баллы НГУ, чтение
локальных YAML FAQ/сокращений, цикл планировщика НГУ и preview его парсера баллов.
Свои FAQ, сокращения, документы и отревьюенные числовые данные можно добавлять
через существующие API. Страница рейтинга НГУ в UI недоступна для custom.
Изменение профиля не очищает ранее загруженные материалы: для пилота другого
вуза нужна отдельная чистая БД/файлы, а не переключение действующего НГУ.

Системный промпт 2.0 параметризует только реквизиты и тематику вуза. При nsu
с дефолтами итоговый текст посимвольно совпадает с 1.0. Общие правила ответа,
инструмент баллов и правила источников сохранены. Поле is_nsu маршрутизатора —
прежнее внутреннее имя контракта, оно не задаёт университет ответа.

## Проверка и эталонный сценарий

Набор НГУ остаётся evals/scenarios.yaml. Для другого вуза добавлен отдельный
набор evals/university_scenarios.yaml, чтобы не запускать несовместимые вопросы
в одном live-прогоне. В нём синтетический Университет Север, не реальный вуз:

1. Задайте custom и названия «Университет Север» через панель.
2. Загрузите текст: «Центр поддержки студентов Университета Север находится
   в корпусе С, кабинет 214», источник https://sever.example/student-support.
3. Выполните `uv run python -m evals.evaluator --scenarios evals/university_scenarios.yaml`.
4. Дополнительно проверьте источники ответа в канале: они должны указывать на
   загруженный документ Север, не НГУ. Автооценка пока проверяет текст ответа;
   она не подменяет ручную проверку источников.

Сценарий не утверждён экспертом; live-прогон не выполнен без материалов и ключей
команды. Тесты проверяют рендеринг обоих вузов, сохранение промпта НГУ и защиту
custom от сидов/локальных файлов/планировщика. На реальной PostgreSQL выполнены
upgrade с нуля (custom) и переход старых настроек (nsu с сохранением версии).
