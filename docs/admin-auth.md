# Первый администратор и приглашения

После применения миграций запустите на доверенном хосте с настройками нужной БД:

```bash
uv run python -m api.auth.bootstrap --username admin
```

Пароль (минимум 8 символов) вводится скрыто с подтверждением. Требуется терминал,
ввод через pipe без терминала отклоняется. Аргумента для пароля нет: не помещайте
секреты в команды, shell history и логи. Username — от 3 до 100 символов.
CLI отключает SQL echo и скрывает параметры запросов в ошибках.

Команда создаёт активного superadmin только при пустой таблице admins. Блокировка
таблицы удерживается до commit, поэтому два одновременных запуска создадут только
один аккаунт. При любом существующем аккаунте (в том числе неактивном или viewer)
команда отказывает с ненулевым кодом выхода, не меняя роли или пароли. Это не
команда восстановления доступа; существующие аккаунты она не сбрасывает.
Ошибка создания откатывает всю транзакцию. Модели и миграции команда не меняет.

Войдите через `/api/v1/auth/login` и создавайте приглашения через админку или
`POST /api/v1/auth/invite` от имени superadmin. `POST /api/v1/auth/register`
всегда требует действующий инвайт, даже в пустой БД; роль берётся из инвайта.
Неизвестный, использованный или просроченный код возвращает 400, занятый username —
409. Инвайт расходуется в той же транзакции, что и создание аккаунта: один код
успешно использует только один конкурентный запрос, ошибка создания сохраняет
инвайт для повторной попытки.

Для Docker демостендов команды приведены в [demo-instances.md](demo-instances.md).
Для Orca используйте только отдельную тестовую БД: общую рабочую БД не очищайте
ради bootstrap и не запускайте на ней тесты.
