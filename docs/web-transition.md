# План перехода на веб-виджет

План по #326 (материал изначально публиковался в #306): рамка,
инвентаризация, макеты и дорожная карта веб-канала. Это документ-план,
не реализация: из него нарезаются задачи на разработку.

## 0. Зафиксированная рамка заказчика (02.11.2026)

Ответы записаны в #326 и приняты как основа этого плана:

- **Веб-канал — встраиваемый виджет** на страницах nsu.ru, а не отдельная
  страница чата на своём поддомене. Отдельная страница отменена
  (abitur-web#24), виджет отслеживается в abitur-web#25.
- **Веб — Релиз 2.** Релиз 1 — Telegram/MAX согласно SRS; на текущем
  демостенде MAX выключен. В Релизе 1 продолжаем вкладываться в ботов,
  новые фичи делаем канал-независимо.
- **Публичный API для виджета — #263**: без него виджету нечего вызывать.

Не подтверждено заказчиком — открытые вопросы (ни один не блокирует #263):

| # | Вопрос | Что от него зависит |
|---|--------|---------------------|
| 1 | Способ встраивания на nsu.ru: iframe на наш домен или JS-скрипт? | Архитектура оболочки виджета (abitur-web#25): iframe переиспользует веб-стек, скрипт — отдельная лёгкая сборка |
| 2 | Кто со стороны университета отвечает за сайт и согласует встраивание? | Сроки этапа интеграции на nsu.ru |
| 3 | Нужен ли вход (аккаунт абитуриента) или чат анонимный? | Перенос истории и подписок между устройствами; анонимный MVP не зависит |

Ключевой вывод, не зависящий от входа: подписка на позицию в конкурсном
списке **не требует аккаунта** — и в мессенджерах она работает по
введённому абитуриентом идентификатору. Вход нужен только для переноса
истории и подписок между устройствами.

## 1. Что уже есть и чего не хватает

### Есть (переиспользуем без переделки)

- **Пайплайн канал-независим.** `pipeline/llm_client.py: ask_local_llm` —
  вопрос → расширение аббревиатур → FAQ-матчер → CRAG/RAG → LLM с
  function-calling. Канал отвечает только за доставку и разметку:
  `bot/formatting.py: format_for_channel` уже разводит «разметку Telegram» и
  «plain-текст» — веб становится третьим значением `channel`, а не отдельной
  веткой логики.
- **FastAPI-контур** (`api/main.py`): CORS, роутеры, settings-API,
  rate-limits уже описаны в таблице `settings`
  (`rate_limit_system_requests_per_day`, `rate_limit_user_requests_per_day`)
  — их остаётся применить к публичному входу (#263).
- **История диалогов** — Redis по `session_id` (24 ч TTL), не привязана к
  Telegram: веб-сессия кладётся в ту же схему.
- **Аналитика** — `message_logs` уже пишет детальный разбор каждого вопроса,
  админка `abitur-web` (Nuxt) показывает статистику. Веб-канал попадает туда
  тем же путём.
- **Отказ уже детектируется** в `pipeline/llm_client.py: _postprocess`
  («не нашёл информации») — веб может оформить это отдельным экраном с
  контактами, не меняя пайплайн.

### Не хватает (это и есть задачи)

- **Публичного чат-API** со стримингом и лимитами — #263, главный блокер.
  Сейчас всё под админ-аутентификацией.
- **Веб-канала форматирования**: `channel="web"` в `format_for_channel` —
  markdown/HTML со ссылками-источниками вместо Telegram-HTML.
- **Оболочки виджета** (abitur-web#25): встраиваемое окно чата с сессиями
  без аккаунта мессенджера, `/reset` и подпиской на позицию.
- **Доставки уведомлений**: сейчас об изменении позиции абитуриента
  уведомляет бот (#285, #292 — надёжность outbox уже чинится). Для веба
  нужен browser-push или email; код принимает/отправляет один и тот же
  `notification_outbox`, меняется только транспорт доставки.
- **Деплоя наружу**: публичный домен + HTTPS для API и оболочки виджета
  (сейчас наружу торчит только админка за VPN, #230).

## 2. Макеты виджета

Интерактивные макеты ключевых экранов: `docs/mockups/web-chat.html`
(открыть в браузере, без сборки). Первый экран показывает виджет на странице
nsu.ru, остальные — его состояния:

1. **Виджет на странице nsu.ru** — плавающая кнопка и открытое окно чата
   поверх контента страницы (постановка рамки из раздела 0).
2. **Окно чата** — приветствие, подсказки-чипсы частых вопросов, поле ввода.
3. **Ответ с источниками** — текст, блок «Источники» (до 3, как в
   мессенджерах), оценка ответа 👍/👎, кнопка «Начать новый диалог»
   (аналог `/reset`).
4. **Отказ** — «не нашёл информации» с контактами приёмной комиссии вместо
   пустого ответа.
5. **Загрузка/стриминг** — «Печатает…» → текст приходит по частям (SSE).
6. **Мобильная версия** — виджет на весь экран телефона, чипсы
   прокручиваются.

## 3. Дорожная карта

Привязка к майлстоунам: ноябрьское демо и декабрьская промежуточная защита
остаются за Релизом 1 (мессенджеры). Веб-виджет — Релиз 2; его календарь
фиксируется при планировании Релиза 2 из этапов ниже.

### Релиз 1 — мессенджеры (текущий)

Telegram/MAX согласно SRS. Основное — качество ответов и надёжность
уведомлений (#285, #292). Новые фичи — канал-независимо, чтобы Релиз 2
получил их бесплатно.

### Релиз 2 — веб-виджет, этапы

**А. Публичный чат-API — #263.** `POST /api/v1/public/chat` со
SSE-стримингом, лимиты `rate_limit_*` из settings, без админ-аутентификации.
Не зависит от открытых вопросов раздела 0 — можно начинать.

**Б. Оболочка виджета — abitur-web#25.** Окно чата по макетам раздела 2
(desktop + mobile, стриминг, отказ-экран), сессии без аккаунта в той же
Redis-схеме. До старта выбрать вариант встраивания (iframe/скрипт) —
открытый вопрос 1; до ответа оболочка живёт на своём стенде и встраивается
куда угодно для демо.

**В. Интеграция на nsu.ru.** Встраивание на страницы приёма после ответов
на открытые вопросы 1–2 (способ и ответственный за сайт). Самый
неконтролируемый по срокам этап — поэтому отделён от Б.

**Г. Подписка и уведомления в вебе.** Форма «идентификатор абитуриента» в
виджете → та же таблица `user_rating` + `notification_outbox`; транспорт
доставки (browser-push/email) — отдельная задача. Вход абитуриента (ЕСИА
или аккаунт) — только если заказчик подтвердит необходимость (открытый
вопрос 3).

### История: первоначальная декомпозиция

Первоначально (до фиксации рамки) предлагались задачи #347–#353 с MVP
отдельной страницы к ноябрьскому демо. По решению команды они закрыты и
реализацией не считаются. Перед закрытием #326 нужно согласовать и
актуализировать декомпозицию Релиза 2 на доске — из этапов А–Г этого плана.

### Риски

- **Согласование встраивания на nsu.ru** может затянуться — поэтому оболочка
  виджета (этап Б) независима от интеграции (этап В) и демонстрируется на
  своём стенде.
- **Без входа нет сквозной аналитики одного абитуриента** между
  устройствами — осознанно принимаем для MVP.
- **Public API — новая поверхность атаки**: лимиты (#263) обязательны до
  открытия, SECRET_KEY/CORS — по #326.
- **Сжатие календаря Релиза 2**: если старт сместится, этап В (интеграция)
  — первый кандидат на перенос.
