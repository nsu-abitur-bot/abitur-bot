# План перехода на веб-панель

План по #306: рамка, инвентаризация, макеты и дорожная карта переноса чата
абитуриента из мессенджеров на веб. Это документ-план, не реализация: из него
нарезаются задачи на разработку (ссылки в разделе 4).

## 1. Рамка: вопросы заказчику и рабочие гипотезы

Ответы заказчика ещё не получены — план строится на рабочих гипотезах ниже.
Каждая гипотеза не блокирует старт этапа 1: MVP от неё не зависит. Ответы
фиксируются в #306 по мере обсуждения.

| # | Вопрос заказчику | Рабочая гипотеза | Что меняется, если нет |
|---|------------------|------------------|------------------------|
| 1 | «Переход» — это **замена** Telegram/MAX или веб **в дополнение** к ним? | Веб в дополнение: мессенджеры живут до конца приёмной кампании 2027, новые фичи делаем канал-независимо | При замене — не вкладываемся в ботов вообще (#230 про websocket закрываем как wontfix), план уведомлений становится обязательным, а не этапом 3 |
| 2 | Форма на сайте: **встраиваемый виджет** на страницах nsu.ru или **отдельная страница** чата? | Отдельная страница чата на своём поддомене; виджет — потом | Виджет требует согласования встраивания стороннего кода с владельцами сайта — этап 2 сдвигается вправо |
| 3 | Кто со стороны университета отвечает за сайт и как встраивается сторонний код (скрипт, iframe, поддомен)? | Подразумеваем iframe на наш поддомен — минимальное вмешательство в nsu.ru | Если только скрипт — переписываем этап 2 на JS-виджет с самого начала |
| 4 | Нужен ли **вход** (аккаунт абитуриента) или чат анонимный? | MVP анонимный: сессия = cookie/browser, история и подписки привязаны к идентификатору сессии, как сейчас к chat_id | Если нужен вход сразу — добавляется интеграция ЕСИА/аккаунта до MVP, ноябрьское демо сдвигается |

Ключевой вывод по рамке: подписка на позицию в конкурсном списке **не требует
входа** — и в мессенджерах она работает по введённому абитуриентом
идентификатору, а не по аккаунту. Вход нужен только для переноса истории и
подписок между устройствами, поэтому он в этапе 3.

## 2. Что уже есть и чего не хватает

### Есть (переиспользуем без переделки)

- **Пайплайн канал-независим.** `pipeline/llm_client.py: ask_local_llm` —
  вопрос → расширение аббревиатур → FAQ-матчер → CRAG/RAG → LLM с
  function-calling. Канал отвечает только за доставку и разметку:
  `bot/formatting.py: format_for_channel` уже разводит «разметку Telegram» и
  «plain-текст» — веб становится третьим значением `channel`, а не отдельной
  веткой логики.
- **FastAPI-контур** (`api/main.py`): CORS, роутеры, settings-API,
  rate-limits уже описаны в таблице `settings`
  (`rate_limit_system_requests_per_day`, `rate_limit_user_requests_per_day`)
  — их остаётся применить к публичному входу (#263).
- **История диалогов** — Redis по `session_id` (24 ч TTL), не привязана к
  Telegram: веб-сессия кладётся в ту же схему.
- **Аналитика** — `message_logs` уже пишет детальный разбор каждого вопроса,
  админка `abitur-web` (Nuxt) показывает статистику. Веб-канал попадает туда
  тем же путём.
- **Отказ уже детектируется** в `pipeline/llm_client.py: _postprocess`
  («не нашёл информации») — веб может оформить это отдельным экраном с
  контактами, не меняя пайплайн.

### Не хватает (это и есть задачи)

- **Публичного чат-API** со стримингом и лимитами — #263, главный блокер.
  Сейчас всё под админ-аутентификацией.
- **Веб-канала форматирования**: `channel="web"` в `format_for_channel` —
  markdown/HTML со ссылками-источниками вместо Telegram-HTML.
- **Поверхности чата**: страница (и позже виджет), сессии без аккаунта
  мессенджера, `/reset` и подписка на позицию в веб-интерфейсе.
- **Доставки уведомлений**: сейчас об изменении позиции абитуриента
  уведомляет бот (#285, #292 — надёжность outbox уже чинится). Для веба нужен
  browser-push или email; код принимает/отправляет один и тот же
  `notification_outbox`, меняется только транспорт доставки.
- **Деплоя наружу**: публичный домен + HTTPS для страницы чата (сейчас наружу
  торчит только админка за VPN, #230).

## 3. Макеты веб-панели

Интерактивные макеты ключевых экранов: `docs/mockups/web-chat.html`
(открыть в браузере, без сборки). Экраны:

1. **Окно чата** — приветствие, подсказки-чипсы частых вопросов, поле ввода.
2. **Ответ с источниками** — текст, блок «Источники» (до 3, как в мессенджерах),
   оценка ответа 👍/👎, кнопка «Начать новый диалог» (аналог `/reset`).
3. **Отказ** — «не нашёл информации» с контактами приёмной комиссии вместо
   пустого ответа.
4. **Загрузка/стриминг** — «Печатает…» → текст приходит по частям (SSE).
5. **Мобильная версия** — тот же чат в узком экране, чипсы прокручиваются.

ASCII-выжимка экрана чата:

```
┌──────────────────────────────────────────────┐
│ ● Бот абитуриента НГУ            [нов. диалог]│
├──────────────────────────────────────────────┤
│                                              │
│         Привет! Спрашивай о поступлении,     │
│         я отвечу по документам НГУ.          │
│                                              │
│  [Проходные баллы] [Общежития] [Документы]   │
│                                              │
│                    Какой проходной на ФИТ? ▕▏│
│                                              │
│  ▌Проходной балл на ФИТ 2026 — 272 …        │
│  ─ Источники ──────────────────────────      │
│  📄 Итоги приёма 2026 · nsu.ru               │
│  👍 👎                                       │
├──────────────────────────────────────────────┤
│ [ Спроси о поступлении…            ] [ ➤ ]   │
└──────────────────────────────────────────────┘
```

## 4. Дорожная карта

Этапы привязаны к майлстоунам курса. Задачи заведены на доске и ссылаются
на #306.

### Этап 0 — рамка (сейчас)

Подтвердить у заказчика 4 гипотезы из раздела 1. Не блокирует этап 1:
MVP-объём (анонимная отдельная страница) — пересечение всех вариантов ответов.

### Этап 1 — MVP чата в браузере → демо в ноябре

Контрольная точка: в браузере на демо вопрос → стримящийся ответ с
источниками; лимиты частоты держатся.

| Задача | Содержание |
|--------|-----------|
| #263 Публичный чат-API | `POST /api/v1/public/chat` с SSE-стримингом; лимиты `rate_limit_*` из settings; без админ-аутентификации |
| #347 Веб-канал форматирования | `format_for_channel(channel="web")`: markdown + источники ссылками; переиспользовать `_visible_sources` |
| #348 Страница чата | По макетам из раздела 3: desktop + mobile, стриминг, отказ-экран |

### Этап 2 — сессии и интеграция на nsu.ru → промежуточная защита в декабре

Контрольная точка: чат доступен по адресу университета (или на staging с
согласованным вариантом встраивания), история диалога живёт между
перезагрузками.

| Задача | Содержание |
|--------|-----------|
| #349 Анонимные сессии | `session_id` веб-чата → та же Redis-история, `/reset` = «новый диалог»; TTL как сейчас |
| #350 Интеграция на nsu.ru | Отдельный поддомен или iframe на страницах приёма — по ответу заказчика на вопрос 3; согласование с владельцами сайта |
| #351 Подписка на позицию в вебе | Форма «идентификатор абитуриента» в веб-чате → та же таблица `user_rating` + `notification_outbox` |

### Этап 3 — вход и уведомления → весна (Демо · март, Защита · май)

| Задача | Содержание |
|--------|-----------|
| #352 Транспорт уведомлений | Browser-push/email из `notification_outbox` (дополняет #285/#292), повторы и троттлинг уже в outbox |
| #353 Вход абитуриента | ЕСИА или аккаунт — если заказчик подтвердит вопрос 1/4; перенос истории и подписок между устройствами |
| Судьба мессенджеров | Решение по Telegram/MAX после данных о доле веб-канала в `message_logs`: оставить, заморозить или вывести |

### Риски

- **Согласование встраивания на nsu.ru** может затянуться — MVP живёт на
  своём поддомене и от этого не зависит.
- **Без входа нет сквозной аналитики одного абитуриента** между устройствами —
  осознанно принимаем для MVP.
- **Public API — новая поверхность атаки**: лимиты (#263) обязательны до
  открытия, SECRET_KEY/CORS — по #326.
