# Runbook: что делать по алерту

Регламент для любого члена команды: цель — за 15 минут либо починить,
либо откатиться. Никаких обязательных летних дежурств (#243): система
должна быть починяемой по этому документу.

Все команды выполняются на сервере по SSH в каталоге с `docker-compose.yml`.

## Как приходят алерты

Планировщик раз в минуту проверяет пробу живости API и долю ошибок в
ответах; при проблеме бот присылает сообщение в командный чат
(`ALERT_CHAT_ID`). Повтор одного и того же алерта — не чаще раза в
`ALERT_REPEAT_MINUTES` (по умолчанию 30), чтобы инцидент не залил чат.

## Алерт: «API не отвечает» / «API отвечает кодом N»

Симптом: проба `/health` недоступна или возвращает не 200.

1. `docker compose ps` — у каких сервисов `unhealthy`/`Restarting`.
2. `docker compose logs api --tail 100` (и `bot`, если он unhealthy) —
   что падает: ошибка старта, БД, нехватка памяти.
3. **Если после недавнего релиза** — откат одной командой (#244):
   ```sh
   /usr/local/sbin/abitur-deploy --rollback backend
   ```
   Миграции автоматически не откатываются, состояние БД совместимо по
   принципу «вперёд».
4. Если проблема не в релизе (диск, память, БД):
   - `docker compose restart api bot` — чаще всего достаточно;
   - `df -h`, `free -m` — кончилось место/память: почистить `./logs`,
     старые образы (`docker image prune` — осторожно, не трогая образы
     из receipt, см. [backup](backup.md) и deploy README);
   - PostgreSQL не поднимается — восстановить из слепка:
     [docs/backup.md](backup.md), раздел «Восстановление».

## Алерт: «Доля ошибок за N мин: X из Y вопросов»

Симптом: >20% ответов за последний час — ошибки (сбой модели, недоступность
базы знаний). Бот отвечает «сервис недоступен»/«LLM временно недоступна».

1. Посмотреть, что именно: `GET /api/v1/logs/answer-stats?group_by=hour`
   (с сервера: `curl http://127.0.0.1:8000/api/v1/logs/answer-stats?group_by=hour`).
2. `docker compose logs bot --tail 200 | grep -i error` — типичная причина:
   закончившийся лимит/баланс LLM-провайдера или недоступность его API.
   Провайдеры переключаются в админке («Подключения → Модели»), без релиза.
3. Если ошибки начались после релиза — откат (#244, команда выше).
4. Ошибок мало, но алерт повторяется — порог регулируется
   `ALERT_ERROR_THRESHOLD` / `ALERT_MIN_QUESTIONS` в `.env`.

## Алерт: «Метрики ответов недоступны»

Сам планировщик не достучался до `/answer-stats`. Смотреть пункт «API не
отвечает»: если API жив, а эндпоинт падает — это ошибка релиза, откат.

## Не помогает

- Последний хороший слепок: `ls backups/` и [docs/backup.md](backup.md).
- Логи всех процессов: `docker compose logs --tail 200`.
- Переезд на другой сервер: раздел «Переезд» в [docs/backup.md](backup.md).
- Признаться в чате, что регламент не помог — и дополнить этот документ.

## Проверка алертов руками

```sh
docker compose exec scheduler python - <<'PY'
import asyncio
from scheduler.monitor import check_once, _aiohttp_fetch
print(asyncio.run(check_once(_aiohttp_fetch, "http://api:8000")))
PY
```

Пустой список — проблем нет. Настройки: `ALERT_*` в `.env`
(см. `.env.example`).
