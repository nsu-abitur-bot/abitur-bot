# Подготовка пилота #470 после перехода на Cloud.ru

На 20 ноября подготовлены код ограничителя, план и шаблон отчёта. Пилот и
пересчёт индекса не запускались. Сервер и рабочие стенды не менялись.

## Что изменилось в ограничителе

Cloud.ru учитывается отдельно от DeepSeek. Перед каждым физическим запросом
резервируются embedding-токены и рубли. После ответа резерв сверяется с usage.
Неизвестный расход, ошибка, другая модель или неверные векторы блокируют
последующие запросы всех провайдеров. Неопределённый резерв сохраняется после
перезапуска. CNY и RUB не складываются.

Разрешён только HTTPS POST `/v1/embeddings` на
`foundation-models.api.cloud.ru`, модель `ai-sage/Giga-Embeddings-instruct-3B`,
пакет до 16 строк, результат размерностью 2048. Остальные адреса и параметры
отклоняются до отправки. Тексты и векторы в бюджетный журнал не записываются.

По умолчанию Cloud.ru запрещён. Для включения нужны отдельное согласование
рублёвого бюджета, тариф и локальный публичный tokenizer с проверенными SHA256,
версией и соответствием модели Cloud.ru. Похожее название модели на Hugging Face
само по себе соответствие не подтверждает. Подсчёт включает специальные токены.
Отсутствие файла или несовпадение хеша останавливает запрос до сети.

Политика бюджета имеет schema=2. Старый файл schema=1 не мигрирует и не
обнуляется автоматически. Новый файл нельзя создавать вместо старого для
обхода занятого резерва. Оператор сначала должен сверить прежние расходы.
Все процессы используют один файл бюджета и один межпроцессный ограничитель.
Проверка на фиктивных ответах не подтверждает биллинг живого API.

## План малого пилота

Исполнитель пилота - Михаил. Марат готовит индекс, открывает нужные API после
получения проверенной версии, лимитов и явного разрешения запуска, а после
завершения или остановки закрывает подключения.

1. Получить от Марата версии образа и кода, хеши индекса и настроек, подтверждение
   размерности 2048 и переключения обоих embedding-провайдеров. Старый индекс
   остаётся для отката. Получить публичный tokenizer и подтверждение его привязки
   к модели. Проверить ограничитель без сети на выбранном образе, общий файл
   бюджета для API, bot и worker, остановку и сохранение резерва при ошибке.
2. Проверить наличие источников для двух RAG-вопросов и SQL-данных для tools.
   Выбрать публичный run_id. Команда ниже выводит только план, хеши и расчёты,
   не создаёт бюджет и не обращается к API:

   ```text
   uv run python -m tools.release470_plan --run-id eval470-example
   ```

   До инициализации живого бюджета при необходимости заменить вопросы в плане,
   проверить шесть уникальных хешей и зафиксировать окончательный вариант.
   После инициализации менять вопросы или заново создавать бюджет нельзя.
3. Только после согласования Cloud.ru, готовности среды и отдельного разрешения
   запуска выполнить последовательно шесть вопросов из таблицы. Никаких
   нагрузочных серий и повторного прогона 50 эталонов.
4. Проверить распространение правки FAQ между отдельными API и bot процессами,
   доставку полного ответа, сессии и согласованные проверки восстановления.
   Заполнить [шаблон отчёта](470-final-report-template.md), сверить расходы и
   передать Марату на ревью. Полный RTO/RPO отмечать только при фактическом
   выполнении восстановления и проверки ответа через bot.

| Сценарий | Вопрос | Что проверяем |
| --- | --- | --- |
| faq-1 | EVAL470-{run_id}: контрольный FAQ до правки | Ответ v1 из временного FAQ в тестовой БД |
| faq-2 | EVAL470-{run_id}: контрольный FAQ после правки | Второй алиас той же записи, ответ v2 после правки, отдельный bot процесс |
| rag-1 | Какие профили бакалавриата есть на ФИТ? | Ответ по источнику в новом индексе |
| rag-2 | Какие языки программирования изучают на ПИиКН? | Ответ по источнику в новом индексе |
| tools-1 | Какие направления бакалавриата есть на ФИТ НГУ? Укажи коды. | Фактический вызов get_education_programs |
| tools-2 | Какие проходные баллы прошлых лет есть для ФИТ? | Фактический вызов get_admission_scores |

Оба алиаса FAQ заранее относятся к одной временной записи. До правки оба
возвращают v1, после - v2. Эталон нельзя подставлять прямо в ответ приложения.
Вопросы RAG/tools считаются покрытыми по фактическому пути выполнения. Если
приложение выбрало FAQ, не следует отключать FAQ ради нужной отметки. В отчёте
остаётся непроверенный путь и причина. Числа по проходным баллам не угадываются.

Для каждого вопроса сохраняются маршрут, завершённость и время полного ответа,
число попыток, токены, CNY и RUB. Шесть вопросов позволяют проверить работу
цепочки, но не дают достоверного p95 и максимального числа пользователей.

### Условия остановки

- Нет подтверждённого usage, тариф неизвестен или расход больше резерва.
- API вернул ошибку, неизвестную модель, неправильную размерность или неполный ответ.
- Нарушен общий бюджет, изменились хеши, обнаружен второй файл бюджета.
- Нарушены серверные пороги памяти или затронуто окружение вне тестового.

После остановки новые запросы не отправляются. Резерв не снимается автоматически.
Марат закрывает подключения. Повтор возможен после разбора причины и отдельного
решения, без обхода runner или серверной защиты.

## Два отдельных бюджета

По [каталогу Cloud.ru](https://cloud.ru/products/evolution-ai-factory/catalog-foundation-models)
на 20 ноября входные токены выбранной модели стоят 32,22 ₽ за миллион,
выходные бесплатны. Перед запуском оператор подтверждает тариф своего аккаунта.
Сумма каждой физической попытки округляется вверх до микрорубля.

### Пилот: предложение для согласования

Cloud.ru: до 10 000 embedding-токенов суммарно, до 512 на вопрос, потолок 1 ₽.
Расчёт по общему объёму - 0,3222 ₽, с округлением до 512 физических попыток
верхняя оценка менее 0,322712 ₽. Setup и любые повторы входят в общий лимит.
Это предложение, разрешение на расходы Cloud.ru ещё не получено.

DeepSeek: сохраняется ранее подтверждённый потолок 3 CNY, до 300 000 входных
и 10 000 выходных токенов, Flash без thinking. Лимит одного вопроса - 32 000
входных и 1024 выходных токена. Старый пакет GigaChat не оплачивает Cloud.ru.
Подтверждение бюджета само по себе не отменяет запрет запуска пилота.

### Пересчёт индекса: отдельное согласование с Маратом

Марат выполняет пересчёт в отдельном каталоге с сохранением SQL, настроек,
индекса и FAQ-кэша. Runner не даёт отдельной команды пересчёта. Обходить его
и самостоятельно запускать миграцию не требуется.

Нужна числовая сводка без текстов и секретов: количество входов и токенов для
чанков, сущностей, связей, FAQ и алиасов, служебных проверок, число пакетов и
предельный объём повторов. Итоговая стоимость:

`сумма ceil(токены_попытки * 3222 / 100) / 1 000 000 ₽`.

Если токены ещё не подсчитаны, грубая верхняя граница - 8192 токена на каждый
вход, включая служебные и разрешённые повторные входы. Это граница контекста,
а не измеренный объём. Фактический подсчёт локальным tokenizer предпочтительнее.

| Условный объём | Стоимость без округления по пакетам |
| --- | --- |
| 100 000 токенов | 3,222 ₽ |
| 500 000 токенов | 16,11 ₽ |
| 1 000 000 токенов | 32,22 ₽ |

Это примеры расчёта, не оценка имеющегося индекса. До числовой сводки нельзя
назвать окончательный бюджет пересчёта. Он не списывается из бюджета пилота.

## Что ещё требуется до запуска

- Ревью новой версии ограничителя и успешная проверка на серверном образе.
- Сводка и отдельный бюджет пересчёта, готовый индекс от Марата.
- Подтверждённая привязка tokenizer, тариф и согласование Cloud.ru для пилота.
- Открытие только нужных API Маратом и явное разрешение запуска от пользователя.

Живой usage, расход, задержки, доставка Telegram и полный RTO/RPO в рамках
этой подготовки не измерялись.

## Проверки подготовки

На Windows выполнены 42 изолированные unittest-проверки: 39 прошли, три
проверки официального Linux encoder пропущены по платформе. Новые проверки
покрывают раздельные CNY/RUB, перезапуск, отказ без Cloud.ru-разрешения,
неизвестный usage, HTTP-ошибку, неверные модель и векторы, отказ до транспорта
при нехватке рублей, настоящий OpenAI embeddings SDK на MockTransport,
локальный tokenizer со специальными токенами и отключением усечения,
привязку шести вопросов и отсутствие разрешения в предложении бюджета.

Ruff, форматирование и целевой Pyrefly прошли. Генератор плана проверен без
сети, пример сохранён в
[pilot-plan-proposal-2026-11-20.json](release-470-data/pilot-plan-proposal-2026-11-20.json).
Пример не является live-конфигурацией. Он не создаёт SQLite-бюджет и не включает
Cloud.ru. Результат Linux CI и ревью актуального коммита проверяются отдельно.
