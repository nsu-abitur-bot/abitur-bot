## Что нужно предоставить для продолжения

Нужен один согласованный набор условий. Полный root, Docker group, секреты
в переписке и управление общими стендами не требуются.

1. **Актуальное окружение измерений.** Готовый изолированный экземпляр НГУ
   либо ограниченный runner для его подготовки и запуска. Отдельные SQL,
   Redis, файлы LightRAG и тестовые аккаунты. Зафиксированные image digest,
   commit, профиль, модели и версия содержимого. Согласованные RAM/CPU,
   порог остановки, общий lock и предел параллельности. Разрешены запуск,
   остановка и получение результатов только своего проекта #470. Не нужно
   держать API, бот и восстановление включёнными одновременно, если проверка
   этого не требует. Самостоятельно останавливать общие демостенды не планируется.
2. **Пустая цель восстановления.** Независимые SQL/файловые хранилища и разрешённая
   согласованная копия, совместимая с выбранным кодом. Использовать тестовые
   или обезличенные данные. Оператор выполняет восстановление сам либо
   предоставляет строго ограниченную операцию: фиксированная цель, проверка
   её отличия от общих томов и #388, запрет произвольных DSN и путей.
   Старый `tools.restore` с `--clean` нельзя запускать на неподтверждённой цели.
3. **Тестовые каналы и аккаунты.** Отдельные разрешённые боты Telegram/MAX,
   получатели, согласие на сообщения и тестовые роли сотрудников. Конкретные
   токены и пароли остаются у оператора в закрытой конфигурации. Не читать
   и не переиспользовать `with-kb-admin.json` из #388 для новой задачи.
4. **Несекретный экспорт конфигурации.** Commit/digest, профиль НГУ, точные
   модели генерации/CRAG/FAQ-эмбеддингов/LightRAG-эмбеддингов, режим thinking,
   имена провайдеров, hostname API без query/учётных данных, версии схемы и БЗ.
   Образцы переменных без значений ключей не заменяют этот список.
5. **Числовые экспорты.** Подходящие история сквозных проб Telegram/MAX,
   агрегаты пользователей, вопросов, отзывов, ошибок и времени. Нужны период,
   часовой пояс, пропуски, размер выборки и правило исключения тестового трафика.
   Без текстов сообщений, личных идентификаторов и сырых runtime-логов.
   Если разбиение по каналам отсутствует, это отмечается явно. Если календарной
   истории нет, согласовать сбор с владельцем мониторинга либо перенос пункта.
6. **Решение по пилоту.** После подтверждения моделей и тарифа согласовать
   денежный предел ниже. Если условия не удаётся подготовить, нужны конкретные
   ответы по каждому пункту и ответственный, а не общее утверждение о снятии блокеров.

Эти условия пока не подтверждены. Владельца серверной подготовки и отсутствующих
экспортов нужно назначить отдельно, он не назначается этим документом.

## Предложение малого пилота

До шести доставленных ответов: FAQ/RAG/tools в двух тестовых каналах.
Фактический путь подтверждается trace. Пилот не является приёмкой p95 или
полного качества. После него размер основной серии определяется только
недостающими метриками и отдельно согласованной нагрузкой.

На вопрос сохраняются пределы #390: до 40 генераций, 32000 входных и
1024 выходных токенов DeepSeek, 512 токенов эмбеддингов. Для всего пилота,
включая подготовительные вызовы, предлагаются пределы: 300000 входных,
10000 выходных токенов DeepSeek, 10000 токенов эмбеддингов и максимум
**3 CNY DeepSeek**. Покупка пакетов GigaChat не предлагается.

[Расчёт](release-470-data/pilot-budget-2026-11-15.json) использует опубликованные
15 ноября [ставки DeepSeek в CNY](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/):
пиковый тариф без скидки за кэш. Для шести вопросов при их пределах получается
0,433152 CNY для `deepseek-flash` или 1,893888 CNY для `deepseek-v4-pro`.
С общим резервом подготовки - 0,68 или 2,97 CNY соответственно.
Это условные сценарии, фактическая модель стенда пока неизвестна.
Историческую стоимость и имя модели из #388 не переносить на новый запуск.

Для действующего пакета физлица 700 RUB за 50 млн токенов эмбеддингов
10000 токенов соответствуют 0,14 RUB по
[тарифу GigaChat](https://developers.sber.ru/docs/ru/gigachat/tariffs/individual-tariffs).
Это эквивалент использованной части пакета, не цена покупки и не подтверждение
тарифа конкретного аккаунта. Для другого аккаунта/платформы нужен его тариф.
Разные валюты не суммируются, баланс и ключи не читались.

Бюджет пока не согласован. До запуска требуется действующий ограничитель:
учёт всех физических попыток и повторов до отправки, резервирование токенов,
общий денежный предел, остановка при неизвестном usage и запрет неучтённых
подготовительных операций. Готовность такого исполнения здесь не заявляется.
Нативный web search, OCR, PDF, судья и индексация в пилот не входят.

## Проверки подготовки

`tools/release470_inventory.py` использует только стандартную библиотеку.
На сервере он прочитал `/proc/meminfo`, метаданные четырёх фиксированных путей
и результат `sudo -n -l`, из которого в отчёт попали только разрешённые флаги.
Он не импортирует приложение и не открывает конфигурацию wrappers.
Скрипт выполнен через SSH stdin, без установки файлов на сервер.

Ruff, проверка форматирования и целевой Pyrefly для Linux прошли.
Для Pyrefly явно исключены только node_modules: стандартное исключение скрытых
каталогов иначе пропускает временный worktree `.work`. Конфигурация проекта
не менялась. Проектные pytest и offline-проверки выполняются штатным CI PR.

## Как завершать задачу

После предоставления условий выполнить только недостающие измерения,
сохранить версии и артефакты, передать отчёт Марату на ревью. Показатель,
не достигший цели, остаётся результатом измерения. Неизмеренный показатель
остаётся непроверенным. Переносы требуют отдельного принятого решения
с ответственным. Текущая подготовка не является завершением #470.
