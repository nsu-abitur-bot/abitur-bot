# Проверка изолированных вариантов #388

## Девять источников после загрузки

После остановки и повторного запуска проверены 9 документов в PostgreSQL
и LightRAG. Тексты и хеши совпадают со снимками. Сохранены 124 вектора чанков,
2148 узлов и 2404 связи с векторами. Оба тестовых варианта остановлены.

- `graph-integrity-after-nine.json`: полная сверка файлов графа и записей SQL.
- `runtime-after-nine.json`: конфигурация, счётчики и хранилища после перезапуска.
- `all-nine-indexing-summary.json`: известный расход по всем сохранённым попыткам,
  включая первый пилот, восстановления и две прерванные команды.
- `remaining-eight-01-*`, `remaining-eight-02-*`: отчёты прерванных команд.
- `vector-repair-01-*`, `graph-replay-01-*`: восстановление векторов и математики.
- `recovery-math-01-result.json`, `recovery-math-02-result.json`: отказ защитной
  проверки и последующее завершение связи с SQL через проверенный документ.
- `DOC-*-result.json`, `DOC-*-usage.jsonl`, `DOC-*-memory.jsonl`: отдельные
  процессы для приёма, заселения и ФИТ. OOM в успешных процессах не зафиксирован.
- `checkin-attempt-01-*`: сохранённая попытка с ошибкой резервного копирования,
  до обращений к моделям.

У прерванных команд итоговый JSON остался в состоянии `started`.
Их записанные запросы сохранены в JSONL, загрузка завершена следующими этапами.
Полнота последних запросов при двух прерываниях не доказана.
Расчёт стоимости не подтверждает списания с баланса провайдера.

Подробности и команды для проверки:
[загрузка источников](../388-indexing-eight-2026-11-07.md).
Прогоны вопросов и LLM-судьи пока не выполнялись.

## Первичная подготовка и пилот

07.11.2026. Отчёты получены собственным read-only инструментом внутри
двух тестовых контейнеров. В них только разрешённые несекретные настройки,
количества строк, идентификаторы хранилищ и лимиты cgroup.

- `runtime-with-kb.json`: вариант, предназначенный для загрузки документов.
- `runtime-empty-kb.json`: пустой контрольный вариант.
- `preflight.json`: список моделей DeepSeek и HEAD-проверки девяти источников.

В момент проверки оба варианта пустые. Общих хранилищ документов между ними
нет, общий только том блокировки запросов GigaChat. Значения ключей, пароли,
сессии, истории пользователей, полные env и runtime-логи не выгружались.

Эти отчёты подтверждают устройство окружения. Они не измеряют качество
ответов, стоимость индексации, квоты или производительность моделей.

## Измерение индексации

- `index-attempt-01-*`: первая попытка, остановленная локальным лимитом 64.
- `index-attempt-02-*`: повторное принятие того же источника, HTTP 200.
- `indexing-summary.json`: суммарные фактические usage, включая неудачную попытку,
  и расчёт цены по опубликованным ставкам. Баланс провайдеров не проверялся.
- `runtime-after.json`: один processed в графе и один проиндексированный документ
  в SQL после остановки и повторного запуска. Векторы и содержимое документов
  в отчёт не копировались, только имена и размеры файлов.
- `remaining-eight-estimate.json`: прогноз по объёму восьми оставшихся источников,
  тарифные сценарии и ограничения экстраполяции с одного документа.

Прогноз не включает ответы бота, LLM-судью, PDF или полные прогоны набора.
