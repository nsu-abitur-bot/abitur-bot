# Результат пилота 10+10, 10 ноября 2026

Пилот завершён: десять одинаковых вопросов проверены с базой и без базы.
С базой судья засчитал 5/10, без базы - 0/10. Все двадцать ответов и оценок
сохранены, ошибок учёта расхода нет. Полный набор из 50 вопросов не запускался.

## Причина прошлой остановки

В добавленном счётчике токенов была ошибка: он разбирал сырые транспортные
байты как SSE, хотя HTTPX ещё не распаковал сжатый ответ. SDK распаковывал
этот же поток и получал ответ, а счётчик не находил usage и `[DONE]`.
Из-за этого следующий вызов блокировался с `IncompleteEvaluationStream`.

Причина подтверждена коротким запросом на сервере со старым счётчиком:
DeepSeek использовал zstd, SDK прочитал три кадра и один символ ответа,
счётчик не распознал ни одного JSON-события. Локальный тест со сжатием gzip
также воспроизвёл ошибку до исправления. Теперь счётчик распаковывает свою
копию потока отдельным декодером HTTPX. Байты для SDK остаются прежними.
В завершённом пилоте все 30 потоковых вызовов имели zstd и полный usage.

Прошли 46 целевых тестов, включая gzip, deflate и zstd, отсутствующий usage,
оборванный поток и ошибку внутри SSE. Прошли Ruff и Pyrefly для Linux.
Исправление и исполнитель: `af68b13a373fdc68a6e80b685a8076b084ae8bb7`.

HTTP 500 первой попытки был отдельной ошибкой. Её расход, расход неучтённого
потока второй попытки и короткой диагностики не объявляются нулевыми.
Предыдущие отчёты и журналы сохранены.

## Условия проверки

Образ: `sha256:1cb5ec2afa7d624bae29bb7ef6bdbb7139d4c58e32e8202ea6085363c4e38e18`.
Версия приложения: `bfe4f8a088076f8b94056815ca27c613712e1a03`, старше проверенного main.
Результаты относятся к этому образу. Промпты, настройки и эталоны во время
пилота не менялись. Исполнитель допускает только фиксированные десять вопросов.

Повторный осмотр подтвердил одинаковый код и параметры моделей в двух условиях,
девять источников в SQL и графе с базой, пустые SQL документов и граф без базы.
FAQ и история были пусты. Две записи служебных логов первой попытки сохранены,
их количество и точная сессия проверены. Они не используются как история ответа.
Документы заново не загружались. Кэши уже подготовленного графа сохранялись,
поэтому это не измерение полностью холодного окружения.

Каждый вопрос получал новую сессию. Ответ строился через продуктовый пайплайн,
эталон передавался только судье. Параллельность - один вопрос, таймаут ответа
вместе с оценкой - 90 секунд, автоматических повторов вопросов не было.
Калибровка судьи прошла 4/4 в каждом условии.

который действовал во время запуска. В сумму входят восемь калибровок,
ответы со всеми промежуточными вызовами и двадцать оценок судьи.
Всего 371 HTTP-попытка: 279 генераций, 90 embeddings и два OAuth.

За прошлые неуспешные попытки остаются 0,011302 CNY по полным usage и три

С базой worker достиг лимита RAM и использовал swap. Счётчик достижения
лимита срабатывал 1 767 раз, OOM не было. Минимум доступной RAM хоста по
выборке - 838 MiB. Двадцать вопросов выполнены, но устойчивость одного
процесса на пятидесяти вопросах не проверена.

## Оценка будущего прогона 50+50

Для каждого условия документная часть пилота умножена на 45/8, специальная -
на 5/2. Калибровка учтена один раз на условие. Это сохраняет состав 45+5,
а не просто умножает стоимость десяти вопросов на пять.

Ожидание при прежних настройках: около 973 тыс. входных и 44 тыс. выходных
токенов DeepSeek, 18 тыс. токенов GigaChat. Расчёт для DeepSeek:

- 0,79 CNY вне пика при наблюдавшемся кэше
- 1,59 CNY в пик при таком же кэше
- 2,30 CNY в пик без скидки за кэш
- около 4,60 CNY с двойным запасом к последнему сценарию

Для планирования разумно округлить до 5 CNY и 37 тыс. токенов embeddings.
Это оценка, не гарантированная верхняя цена. Текущие 30 CNY превышают этот
расчётный резерв. Повторная индексация и изменение моделей в оценку не входят.
При повторении калибровки на каждой группе из десяти вопросов добавятся
32 запроса судьи, около 0,05 CNY по пиковой ставке без кэша.

По [пакету Сбера для действующих физических клиентов](https://developers.sber.ru/docs/ru/gigachat/tariffs/individual-tariffs)
37 тыс. embeddings эквивалентны примерно 0,52 рубля. Пакет не покупался,
применимый тариф аккаунта и фактический баланс не проверялись.
Саму работу моделей оцениваем примерно в 18 минут последовательно,
без запуска контейнеров, повторов и возможного замедления из-за памяти.

## Что делать дальше

Сначала разобрать пропущенные профили, неправильную цену, поиск договора и
отказы вместо полезной помощи в двух специальных случаях. Перед правками
проверить, что из этого уже изменено в main после тестового образа.
Отдельно проверить спорный зачёт судьи. Пороги 41/45, 5/5 и запрет критических
ошибок не менялись. Прирост минимум 20 п.п. на документных вопросах остаётся
предложением для ревью, а не утверждённым критерием.

Для полного прогона также нужен отдельный исполнитель с учётом большего числа
вызовов и памяти. Сейчас лимит 256 HTTP-попыток почти выбран уже на десяти
вопросах с базой: выполнено 252. Имеющийся runner намеренно не запускает 50.

Оба controller завершились с exit 0 и `cleanup_ok=true`, тестовые проекты
остановлены. Работающие API и web на портах 18001/18003 и 13001/13003 вернули
HTTP 200. НГТУ на 18002/13002 остаётся выключенным коллегой. Общие сервисы,
права, root-wrapper, Wiki и main не менялись. PR и задача открыты, ожидают ревью.
