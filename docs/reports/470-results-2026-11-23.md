## Правка FAQ и кэши

В успешно завершённом сценарии FAQ-2 штатные маршруты auth/FAQ использовались
с той же зависимостью `require_admin`, что и в API. Проверены реальный вход
временного администратора, POST, PUT и DELETE. Полный API lifespan, импортная
очередь, сетевой HTTP listener и остальные маршруты не запускались.

После создания v1 matcher прогрет. Затем запущен штатный `watch_faq_updates`,
выполнен PUT v2 и без ручного обновления получен v2 в matcher и ответе BotCore.
Commit правки: 07:48:23,569470 UTC. К началу вопроса 07:48:23,770393 UTC
новый ответ уже находился в памяти, верхняя граница этого интервала - 0,201 с.
Полный ответ принят Bot API в 07:48:34,829820 UTC, через 11,260350 с от
зафиксированной правки. Это одиночное наблюдение, не постоянный норматив.

Сразу после PUT снимок matcher ещё содержал v1. Поле
`api_cache_matches_new_answer_without_reload=false` отражает именно этот момент.
В данном запуске API и BotCore находились в одном процессе, а watcher затем
обновил тот же matcher. Поэтому нельзя по этому полю объявлять доказанным дефект
отдельного API-кэша. Проверка независимых горячих кэшей остаётся открытой.
