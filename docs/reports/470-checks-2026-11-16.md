## Что выполнено 16 ноября

Команда `primary run probe /evaluation/probe.py` завершилась с кодом 0
за 3,257 секунды. Внутри worker доступны PostgreSQL и Redis, TCP-подключения
к `1.1.1.1:443` и SSH шлюза `172.30.94.1:22` не прошли. Минимальная
доступная память хоста - 1349,7 MiB. Проверены именно эти адреса и порты,
это не доказательство запрета всех возможных сетевых маршрутов.

Затем выполнен [исполнитель проверки доступа](../../tools/release470_auth_probe.py).
Он использует реальные маршруты FastAPI через ASGITransport и реальный
изолированный PostgreSQL. Перед импортами отключены dotenv и SQL echo.
Созданы временные аккаунты superadmin, admin и viewer со случайными
паролями, существующий администратор и его файл учётных данных не использовались.
Пароли, JWT и приглашение оставались в памяти процесса и в отчёт не попали.

[Все 24 проверки прошли](release-470-data/auth-probe-2026-11-16.json):

- Вход трёх ролей, отказ при неверном пароле, неверном JWT и отсутствии входа.
- Viewer читает темы, но не получает доступ к FAQ и списку администраторов.
  Admin читает FAQ, но не создаёт приглашения и не получает список администраторов.
  Superadmin имеет соответствующие права.
- Регистрация без приглашения отклоняется. При двух одновременных запросах
  с одним приглашением проходит только один, роль сохраняется из приглашения.
- После понижения роли старый JWT получает новые ограничения. После деактивации
  старый JWT и новый вход больше не работают.

Тестовые аккаунты и приглашение удалены в `finally`, остался один исходный
администратор. [Исполнение](release-470-data/auth-probe-receipt-2026-11-16.json)
заняло 50,115 секунды, минимум доступной памяти - 1070,4 MiB. Защитная остановка
не потребовалась. Контроль `status` после выполнения не показал контейнеров
ни `primary`, ни `restore`.

Исходник, размещённый в
`/home/mihail/abitur-evals/470-scripts/release470_auth_probe_20261116.py`,
совпадает с файлом PR по SHA256:
`92596a9337944fcad83d71a7cfda822d9708328aa1755dd1ecece0e51f326368`.
Повторять проверку можно только через подготовленный runner на отдельной
тестовой БД. Произвольный запуск на общем стенде не предусмотрен.

Lifespan приложения намеренно не запускался. Поэтому эти результаты не
подтверждают работу фоновых задач, UI, политику CORS, истечение JWT по времени,
обновление кэшей разных процессов, разделение сессий ботов или доставку ответа.
Нельзя использовать 50,115 секунды как задержку ответа пользователю.
Модели, индексация и отправка сообщений не запускались, платных вызовов не было.

Пользователей, сообщений и отзывов нет. Оператор сообщает проверку 11 файлов
LightRAG. Это не повторная проверка восстановления исполнителем задачи.
Количества строк сами по себе не доказывают равенство всего SQL-содержимого.

Резервирование заняло 8,419 секунды, команда восстановления - 5,116 секунды.
Поиск и доставленный ответ после восстановления не проверены. Полный RTO
и RPO не измерены. Тестовые БД - PG17, рабочие - PG15. `pg_dump` 17 из образа
создаёт несовместимый с PG15 `SET transaction_timeout`. Проверка PG17 -> PG17
не подтверждает восстановление в рабочую версию. Повторять её сейчас незачем.

[Агрегаты](release-470-data/operator-source-aggregates-2026-11-15.json):

Границы записей - 1 ноября 04:42:17,015381 и 12 ноября 04:58:30,226981.
Часовой пояс границ не указан. Latency есть примерно у 6,64% записей,
его нельзя автоматически считать временем до доставки ботом.
Тесты не отделены, агрегаты отзывов и ошибок не предоставлены.
Показатели реальной аудитории и сквозной скорости этим экспортом не подтверждены.
