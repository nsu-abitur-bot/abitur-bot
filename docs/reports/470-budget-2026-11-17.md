# Общий учёт расходов для проверок #470

Этот этап закрывает четыре работы по коду: подсчёт входных токенов, сохранение
расходов после обрыва, общий бюджет процессов и offline-проверки SDK/SSE.
Пилот, переиндексация и платные запросы не запускались. На сервере ничего
не устанавливалось и работающие стенды не менялись. Изменения передаются в PR #473.

## Входные токены

`tools/release470_tokens.py` использует официальный
[deepseek-recipe](https://github.com/deepseek-ai/deepseek-recipe/blob/935817c66f5d6e64838f419692545f06787e485f/docs/tokenizer.md)
версии 0.2.0. Он преобразует Chat Completions в полный prompt V4.1, включая
роли, определения функций, tool calls и результаты инструментов, затем считает
token IDs штатным tokenizer. Подсчёт JSON bytes +512 удалён.

Публичный tokenizer включён в `tools/release470_resources` с SHA256 и лицензией
MIT, gzip уменьшает его до 1,87 MB. При подсчёте нет скачивания файлов или
передачи текста внешним сервисам. Версия пакета, файл и формат модели закреплены.
Поддерживается только текстовый non-thinking контракт `deepseek-flash`,
соответствующий DeepSeek-V4.1-Flash-1017. Неизвестные поля, изображения,
prefix continuation, hosted tools, отсутствующий encoder и изменённый tokenizer
останавливают запрос до отправки. Смена модели требует новой проверки контракта.

Количество из encoder резервируется до физического запроса. Полученный usage
сверяется с резервом. При превышении, неизвестной модели или неполном usage
общий бюджет блокируется, сохраняется как минимум полный резерв, а большее
фактически наблюдённое значение не скрывается. Дальнейших запросов нет.
Offline-проверка формата не выдаётся за подтверждение billing usage живого API:
такое сравнение остаётся частью отдельно разрешённого пилота.

## Сохранение и общий бюджет

`tools/release470_store.py` хранит политику, физические попытки, резервы,
итоговые receipts и журнал в одном SQLite-файле. Резерв и запись журнала
коммитятся одной транзакцией до транспорта. Итоговый usage, расходы и флаг
остановки также сохраняются одной транзакцией. Промежуточного журнала со
старыми release totals больше нет. Hash chain и сверка последнего снимка
обнаруживают неполный журнал и несогласованные изменения состояния.

Рабочий budget создаётся явно один раз. Конструктор его не создаёт и не
обнуляет; каталог отчёта больше не определяет бюджет. Повторное создание
существующего файла запрещено. При неопределённом исходе резерв не возвращается.
После обрыва новый процесс видит незавершённую попытку и отказывается тратить
дальше. Сначала нужны достоверный receipt и сверка с оператором. Если usage
восстановить нельзя, резерв остаётся занятым, автоматического reset/force-resume нет.

[Регрессия старого 155b409](release-470-data/budget-restart-regression-2026-11-17.json)
воспроизведена без сети: после смены каталога отчёта 100/10 токенов превращались
в 0/0. Новый тест проверяет сохранение 100/10 при таком же перезапуске.
Другой тест завершает отдельный процесс через `os._exit()`: OS-lock освобождается,
но зафиксированный резерв остаётся и следующая попытка не допускается.

Все API, bot и worker процессы должны открывать **один и тот же** файл
`/reports/release470-budget.sqlite3` на общем локальном томе. SQLite `BEGIN IMMEDIATE`
атомарно проверяет общий и покомпонентные лимиты. Межпроцессный file lock держится
от подготовки wire-request до окончательного usage/закрытия SSE. Физические
запросы малого пилота выполняются последовательно; ожидание ограничено 180 с.
Это соответствует последовательному пилоту, не является проверкой нагрузки.

Сохраняются пределы: 300000 входных и 10000 выходных токенов суммарно,
до 3 CNY; на вопрос 32000/1024 и до40 генераций. Setup тоже расходует общий
бюджет. Пиковый cache-miss расчёт DeepSeek - 2/8 CNY за миллион, по
[официальной странице](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/),
проверенной в этой работе. Валюты не складываются.

GigaChat и Cloud.ru сейчас отклоняются до транспорта. Владелец отказался от
старого пакета GigaChat, а бюджет Cloud.ru/RUB и пересчёт индекса не согласованы.
Наличие поля embedding cap не даёт разрешения расходовать его у другого
провайдера. Разбор OAuth form больше не падает как JSON: операция отклоняется
как неразрешённая текущей политикой, без отправки. Старые инструменты #388
и их учёт не менялись.

## API, бот и фоновые задачи

`tools/release470_runtime.py` - отдельная точка входа для изолированного
исполнения API или бота. Обычные `main.py` и `api/main.py` автоматически её
не включают. Это позволяет сохранить действующие стенды.

Точка входа требует явного `--execute`, фиксированного пути budget и SQL-target
`postgres/eval470`; offline fixture budget не может запускать live-процессы.
Она устанавливает hooks до импорта обработчиков, затем оборачивает
`ask_local_llm`. Неизменяемый plan содержит до шести case IDs и SHA256 ожидаемых
вопросов. Неизвестный вопрос отказывается до пайплайна. Сами тексты в budget
не сохраняются. `ContextVar` сохраняет case ID в дочерних asyncio-задачах после
возврата обработчика; соседний запрос не перезаписывает чужой контекст.

Параметры `_params` ограничиваются остатком, а HTTPX hook повторяет проверку
под общим gate и ограничивает max_tokens **в фактическом wire payload**.
Это исключает гонку со вторым процессом между построением SDK-параметров
и отправкой. Headers/Content-Length и SDK timeout extensions сохраняются корректно.

HTTPX перехватывается на каждой физической попытке, включая native SDK retries.
Requests и непринятые aiohttp/urllib маршруты отказывают. Telegram оставлен
для отдельного ограниченного прокси. Это hooks для проверенных транспортов,
а не замена серверному firewall или защита от произвольного вредоносного кода.
Сырой socket/другой транспорт не должен получать обходной путь к провайдерам.

## Проверки

Локальные unittest запускаются отдельно от pytest conftest, без БД приложения,
ключей провайдеров, dotenv, runtime-логов и сети. Используются временный SQLite,
два настоящих процесса и MockTransport. Проверены:

- общий output cap при двух процессах с разными каталогами отчётов;
- перезапуск, аварийный выход, неизменность расходов и запрет implicit reset;
- атомарный итоговый журнал, unknown model, превышение bound и приватность;
- настоящий DeepSeekProvider/OpenAI SDK, наследование контекста фоновой задачей,
  max_tokens из остатка и отказ для незапланированного вопроса;
- SDK retry после503 без второго физического запроса при неопределённом usage;
- штатный SDK SSE, фрагментированный gzip, отмена до чтения и usage без DONE.
  SDK не получает успешное завершение при неопределённом исходе;
- отказ неразрешённых OAuth, Cloud.ru, requests/aiohttp/urllib до транспорта.

Локально на Windows прошли 23 проверки, 3 теста официального encoder пропущены:
пакет поставляет Linux wheels. Linux CI устанавливает закреплённую зависимость
и выполняет все26, включая реальное кодирование UTF-8, tools и tool history.
Тесты зависят только от файлов Git и временных fixtures, не от ноутбука оператора.
Ruff, Pyrefly и форматирование проверяются для новых модулей и тестов.

## Что требуется перед использованием на сервере

Оператор должен подготовить один общий writable local bind для budget и gate
во всех тестовых процессах, с владельцем runtime UID. Нельзя дать API и боту
разные копии файла или монтировать его на NFS. Исходные архивы, БЗ и #388 не
перемещаются. На общем бюджете журнал и файл gate нельзя удалять при cleanup.

Новый код, native encoder и публичный tokenizer нужно разместить в разрешённом
тестовом runtime и проверить offline на выбранном digest. Старые команды runner
не начинают использовать новые hooks только от наличия файлов в PR. Для
исполнения должны вызываться отдельные точки входа `release470_runtime`, а не
прежние неинструментированные команды. Подключение этих entrypoints к runner
остаётся явной операторской подготовкой; в этой итерации сервер не менялся.

После отдельного разрешения на запуск и этой подготовки API/бот могут запускаться
оператором через `python -m tools.release470_runtime --component api|bot --execute`
в изолированном контейнере. Не выполнять эту команду сейчас: запрет владельца
на пилот остаётся в силе. Ни наличие кода, ни зелёный CI не открывают provider egress.

До пилота также остаются Cloud.ru/RUB, новый индекс2048, отдельное решение о
пересчёте и проверка оператором точечных endpoints. Эти четыре изменения кода
не закрывают #470, не измеряют p95/RTO/RPO и не заменяют ревью Марата.
