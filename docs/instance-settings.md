# Настройки экземпляра

В разделе «Настройки системы → Настройки экземпляра» суперадминистратор задаёт
подключения OpenAI/Gemini, назначение моделей, токены Telegram/MAX, прикладные
прокси, параметры вызовов, загрузки документов и конкурсных списков.
API: `/api/v1/settings/instance` (GET/PUT), `/check` (POST).

Права проверяются сервером: просмотр и изменение подключений доступны только
superadmin. Сохранённый секрет в API — `value: null`, `configured: true`.
Пустое поле в UI сохраняет ключ; кнопка удаления передаёт явный `null`.
Кнопка проверки не сохраняет настройки. Сохранение активного подключения повторно
проверяет доступ к модели/идентичность бота. Неверные настройки не заменяют рабочие.
Проверка LLM выполняет маленький запрос и может расходовать токены.

Конфигурация хранится одной версионированной записью `instance_settings_v1`
в существующей таблице `settings`: отдельная миграция схемы не нужна.
API-ключи, токены и прокси с возможными паролями шифруются Fernet. Мастер-ключ
`SETTINGS_ENCRYPTION_KEY` нужен для сохранения/чтения секретов; потеря ключа
означает необходимость заново вводить подключения. Не храните его вместе с БД.
В логах маскируются текущие и ранее использованные процессом секреты.

## Применение

API, бот и планировщик читают снимок каждые две секунды. Конфликт редактирования
возвращает 409: обновите страницу и повторите правки. Проверки внешних сервисов
не держат блокировку БД; перед записью версия проверяется повторно под lock.
Сбой чтения БД оставляет последний рабочий снимок, а не очищает подключения.

LLM-клиенты используют новые настройки в следующих вызовах. Чат, FAQ-эмбеддинги,
граф, эмбеддинги графа и PDF-парсер могут выбирать провайдеров независимо.
Профили CHAT/GRAPH/PARSER/VISION/INTENT/TITLE/EMBEDDING задаются отдельно.
Смена модели/провайдера эмбеддингов или endpoint при наполненном индексе
блокируется: автоматическая переиндексация в эту задачу не входит.
Для смены пространства эмбеддингов сначала нужна отдельная процедура миграции
индекса. Смена ключа в том же пространстве разрешена.

Супервизор канала сначала отменяет polling и закрывает старую сессию,
затем запускает новое подключение. Без токенов процесс остаётся жив и ждёт
настройки. Дубли polling защищены token-specific файловым lock на одном хосте
и advisory lock в PostgreSQL внутри одного экземпляра/БД. Не выдавайте один
токен независимым стендам на разных хостах и разных БД: общей блокировки у них нет.
Планировщик применяет настройки на границе цикла; изменение будит его ожидание.

Изменение числа воркеров LightRAG применяется при следующем обращении после
завершения активных операций с графом; ручной перезапуск не нужен.
Флаги SEED_* относятся к следующему старту, а не немедленной перезаливке данных.
Поведение/промпты вуза и его стартовое наполнение адаптируются отдельно в #357;
здесь правила ответа не меняются.

## Первое развёртывание и переход с env

1. Подготовьте PostgreSQL, Redis и корневые секреты по `.env.example`.
2. На существующем экземпляре **до первого запуска новой версии** сохраните старый
   `.env`, добавьте в него `SETTINGS_ENCRYPTION_KEY` и выполните:
   `uv run python -m bootstrap.runtime_settings`.
   Импорт переносит только известные прикладные параметры и старые лимиты
   документов. Повторный импорт не перезаписывает запись. Секреты не печатаются.
   Токены импортируются с включёнными каналами; проверьте, что старый бот остановлен
   перед запуском нового процесса.
3. Удалите перенесённые прикладные параметры из `.env`. После загрузки снимка
   **БД имеет приоритет**, даже для очищенного ключа; возврата к старому env-токену нет.
   На новом экземпляре импорт не нужен: API/админка запускаются без LLM/бот-токенов.
4. Через админку задайте подключения и включите нужные каналы.
5. Для отката к старому коду используйте сохранённый старый `.env`.
   Перед изменением мастер-ключа нужна перешифровка: простой заменой ключа в env
   существующие секреты расшифровать нельзя.

## Карта настроек

Полный каталог, типы, значения по умолчанию и группы — `config/instance.py:SPECS`;
он же используется для формы, проверки и импорта. API не принимает неизвестные
ключи. CRAG, FAQ threshold и дневные лимиты остаются в существующих API/экранах
(SettingsService), без второго источника значений. Источники parser/config
и адаптация парсера другого вуза относятся к #357.

В env остаются подключения PostgreSQL/Redis, корневые ключи авторизации и
шифрования, CORS для размещения фронта, пути/тип хранилища, настройки пула БД,
lock-файл и диагностика. Их нужно знать до подключения БД/создания процессов,
либо они описывают конкретное размещение, а не подключение бота или модели.

## Проверка

Автотесты используют настоящую тестовую PostgreSQL. Проверяются шифрование,
права, конфликт версий, отказ провайдера без записи изменений, защита эмбеддингов,
применение профилей, последовательность остановки/старта poller и дедупликация.
Живые проверки выполняются через UI на отдельной QA-базе. Нельзя запускать
тестовый polling на действующем токене: проверка getMe достаточна для проверки
ключа, а переключение polling покрывается контролируемыми адаптерами.
