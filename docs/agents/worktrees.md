# Воркспейсы Orca

Открывай, если работаешь в воркспейсе Orca, а не в основном чекауте.

`orca.yaml` в корне описывает setup-хук для нового воркспейса: он копирует из
корневого чекаута то, чего нет в git (`.env`, `faq/faq_data.yaml`,
`abbrev/abbrev_data.yaml`), и выполняет `uv sync`. Агент не стартует, пока setup
не завершился (`setupAgentStartupPolicy: wait-for-setup`), поэтому `uv run`
сразу работает.

Каталог `data/` (хранилище LightRAG) — общий для всех воркспейсов через
`worktree.sharedDirectories`, чтобы не переиндексировать заново.

## Что важно помнить

**БД общая.** PostgreSQL один на всех, из `.env`; отдельного инстанса на
воркспейс нет. Поэтому `alembic upgrade head` из одной ветки видят все
остальные.

**Telegram-поллинг один на токен.** Не запускай `main.py` в двух воркспейсах
одновременно — второй процесс будет отбирать обновления у первого.

**Стек stash общий** с основным чекаутом и другими воркспейсами. Не используй
голые `git stash` и `git stash pop`: можно снять чужие изменения. Лучше
временный коммит.

**Команды запускай из своего воркспейса**, не переходи в корневой чекаут: там
другая ветка и другое состояние рабочего каталога.
