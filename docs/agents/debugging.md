# Логи и отладка

Открывай, когда разбираешься, почему бот ответил не так, как ожидалось.

Файлы пишутся в `logs/` (гитигнорен). Настройка через `LOG_LEVEL` и `LOG_DIR` в `.env`.

| Файл | Уровень | Лимит | Назначение |
|------|---------|-------|-----------|
| `logs/abitur_bot.log` | DEBUG+ | 10 MB × 5 | Основной лог всего приложения |
| `logs/rag_llm_detailed.log` | DEBUG+ | 50 MB × 10 | RAG-контекст, LLM-ответы, FAQ-матчи |
| `logs/errors.log` | ERROR+ | 5 MB × 3 | Только ошибки |

```bash
tail -f logs/rag_llm_detailed.log | grep "<session_id>"   # вся цепочка одного запроса
tail -f logs/rag_llm_detailed.log | grep "RAG retrieval"  # что достал RAG
tail -f logs/rag_llm_detailed.log | grep "CRAG"           # решения CRAG-фильтра
tail -f logs/errors.log                                   # текущие ошибки
```

Разбор одного ответа удобнее начинать с `session_id`: по нему в
`rag_llm_detailed.log` видна вся цепочка — расширение аббревиатур, попадание в
FAQ, что вернул ретривал, решения CRAG и финальная генерация.

## Частые причины непонятного ответа

**«Что-то пошло не так»** — исключение в `ask_local_llm`. Смотри `errors.log`:
чаще всего недоступен Redis, без которого не собирается промпт.

**«LLM временно недоступна»** — упала генерация у провайдера. Типичная причина —
исчерпанная квота: CRAG грейдит каждый чанк отдельным вызовом, и на один вопрос
их уходит больше десятка.

**Ответ без нужного факта** — сначала проверь, что документ вообще в базе
знаний: `GET /rag/docs` и диагностика документа в админке. Отсутствие записи
выглядит в логах так же, как плохой ретривал.
