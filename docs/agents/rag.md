# Пайплайн ответа и RAG

Открывай, когда правишь то, как бот ищет и формирует ответ: `pipeline/llm_client.py`,
`rag/`, `faq/`, `abbrev/` или справочник факультетов.

## Порядок слоёв

`pipeline/llm_client.py:ask_local_llm` — расширение аббревиатур → **FAQ-матчер**
(при попадании отвечает сразу, минуя RAG и LLM) → **RAG** (Corrective RAG
поверх LightRAG, либо обычный LightRAG) → **LLM-генерация** (OpenAI / Gemini) с
доступом к function-calling инструментам.

Порядок не случайный: каждый следующий слой дороже предыдущего, поэтому дешёвый
ответ должен находиться раньше.

## FAQ-матчер

`faq/matcher.py`: эмбеддинги вопросов и alias'ов, косинусное сходство, при
сходстве >= порога — готовый ответ без модели. Порог — `SIMILARITY_THRESHOLD`
(0.95: ниже FAQ отдаёт готовый ответ на соседние вопросы с другим смыслом —
замер в комментарии у константы), поверх него env `FAQ_SIMILARITY_THRESHOLD`, поверх env — ключ
`faq_similarity_threshold` в таблице settings (админка, `PUT /api/v1/settings/faq`).
Бот перечитывает порог перед каждым вопросом, как CRAG, — рестарт не нужен.

Доля вопросов, закрываемых FAQ, — `GET /api/v1/logs/faq-stats`
(числитель `faq_match`, знаменатель `user_input` в message_logs).

`ask_local_llm` только выстраивает порядок; каждый шаг — отдельная функция:

| шаг | функция |
|---|---|
| раскрыть аббревиатуры | `_expand_abbrevs` |
| ответить из FAQ | `_answer_from_faq` |
| найти контекст | `_retrieve_context` |
| собрать промпт | `_build_messages` |
| сгенерировать с инструментами | `_run_tool_loop` |
| привести ответ в порядок | `_postprocess` |
| сохранить историю | `_store_answer` |

История из Redis — только контекст: текущий вопрос `_build_messages` добавляет
сам, всегда последним (из истории его убирает `_history_before_question`).
Сбой Redis на записи или чтении истории ответ не роняет — бот отвечает без неё.

`_build_messages`, `_postprocess` и `_run_tool_loop` проверяются в
`tests/pipeline/test_answer_steps.py` без базы, поиска и сети — если правишь
логику ответа, начинай с теста там.

Тексты промптов — системный промпт с правилами ответа консультанта, хинты
RAG-запроса, интент-маршрутизатор — лежат в `pipeline/prompts.py`, с версией у
каждого и картой блоков в комментариях (#313). Сборка осталась в
`_build_messages` и `_retrieve_context`.

## LightRAG

`rag/graph_memory.py` хранит и граф сущностей/связей, и векторный индекс чанков —
единым встроенным стором на диске (`data/lightrag/<graph_id>/`,
`graph_id="abitur_kb"`). Отдельного ChromaDB нет. Чанкинг внутри LightRAG
(`chunk_token_size=400`, overlap 50).

Опционально `LIGHTRAG_STORAGE=postgres` переносит KV-сторы и `doc_status` в
PostgreSQL (JSONB-таблицы `lightrag_*`, базы знаний разделены колонкой
`workspace`). Векторный индекс и граф остаются файловыми, pgvector не нужен:
VDB-таблицы создаются заглушками. По умолчанию — прежний файловый режим.
Существующие JSON-данные переносит
`uv run python -m rag.migrate_json_to_pg` (идемпотентно, есть `--dry-run`).

**Сбой и пустота — разные состояния.** `query*` в `GraphMemory` при сбое
поиска бросают `RetrievalError` (LightRAG сам ловит исключения запроса и
возвращает `status="failure"` — это проверяется), а «ничего не нашлось»
возвращают пустой строкой. `_retrieve_context` на пустоту кладёт в промпт
`RAG_CONTEXT_NOT_FOUND`, на сбой — пишет ERROR и отвечает
`RAG_UNAVAILABLE_ANSWER` без вызова модели (#282). Адаптеры эмбеддингов при
ошибке падают, а не возвращают нулевой вектор: в nano_vectordb он даёт
NaN-скоры (#283). Документ, который LightRAG при вставке пометил FAILED,
`save` удаляет целиком и возвращает False.

Список документов и полные тексты читаются в потоке (`asyncio.to_thread`), а
соответствие «ссылка → заголовок» для блока «Источники» кэшируется: на каждом
запросе проверяется только дешёвая сигнатура (mtime KV-файлов или
`count/max(updated_at)` в PG-режиме, плюс то же по таблице `document`).

## CRAG

`rag/crag.py` — слой между ретривалом и генерацией:

1. распознаёт факультет и уровень в вопросе по справочнику;
2. сентенс-левел вычищает из чанков предложения про направления **чужих** факультетов;
3. LLM-грейдит релевантность — параллельно, не больше
   `CRAG_GRADING_CONCURRENCY` вызовов одновременно (по умолчанию 5);
4. при нехватке — одна переформулировка и доретрив.

Включается `CRAG_ENABLED` (env) плюс настройки из таблицы `settings`
(веб-админка).

## Справочник факультетов

`Faculty` / `Program`, `db/postgres/services/faculty.py` — авторитетный источник
для CRAG. Редактируется через `/api/v1/faculties`.

При старте выполняется **мягкая** доливка из `db/seed/faculties.json`:
добавляется только недостающее (новые факультеты, алиасы, направления, код у
направления без кода), правки из админки не затираются — поэтому новые записи
сида подхватываются на каждом деплое.

Вручную: `uv run python -m db.seed.load_faculties` (мягко) или `--force`
(жёсткая перезапись, то же делает `SEED_FACULTIES_FORCE=1` при старте).

## Проходные баллы

`AdmissionScore`, `db/postgres/services/admission_score.py`, `parser/scores.py`,
`pipeline/tools/admission_scores.py`.

Числовые баллы вынесены в структурное хранилище и отвечаются function-calling
инструментом `get_admission_scores` из SQL, а не из RAG.

Заливаются автоматически при старте (`bootstrap.seed.seed_admission_scores`, после
справочника — он нужен для матчинга): парсится страница итогов приёма НГУ и
делается идемпотентный upsert. Чтобы рестарты не дёргали сайт, заливка
пропускается, если последняя была свежее `ADMISSION_SCORES_MAX_AGE_HOURS` (24 ч;
отметка — ключ `admission_scores_last_import` в `settings`). Ошибки не роняют
старт.

Сопоставление направления двух видов. **Импорт** матчит строго (точное имя →
профиль → поле, без подстрок): ошибка там записала бы чужой балл. **Поиск** из
инструмента принимает направление в формулировке абитуриента —
`match_programs` в сервисе: после строгих уровней пробует аббревиатуру,
выведенную из названия («ПИиКН», «ПМИ», «КНиС»), код ФГОС и совпадение слов
(«прикладная математика»), и смотрит только направления, по которым есть баллы.
Перед поиском инструмент прогоняет аргументы через расширитель аббревиатур, так
что сокращения из админки работают и здесь. Название факультета в поле
направления («ФИТ») означает все его направления; неверно угаданный факультет не
обнуляет ответ — направление ищется по всему справочнику.

Env: `SEED_ADMISSION_SCORES=0` — выключить, `SEED_ADMISSION_SCORES_FORCE=1` —
игнорировать свежесть, `ADMISSION_SCORES_URL` — другой источник.

Вручную из админки: `POST /admission-scores/preview` → просмотр →
`POST /admission-scores/import`.
