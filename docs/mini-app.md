# Пользовательский API «Инфовуз»

API открывает собственные диалоги Mini App и подаёт вопросы в общий пайплайн
`ask_local_llm`. Он возвращает текст, ссылки из ответа пайплайна и состояние
оценки. Telegram и MAX продолжают вести свои диалоги через Redis. Импорт
переписки из каналов потребует отдельного решения о привязке и переносе.

## Подключение к экземпляру вуза

Применить миграции к базе этого экземпляра и передать процессу API
`MINI_APP_INSTANCE_ID` и `MINI_APP_SHARED_SECRET`. Идентификатор должен быть
стабильным для этого экземпляра и уникальным среди вузов. Случайный секрет
(например, `openssl rand -hex 32`) и тот же идентификатор передать доверенному
Nitro-серверу как `NUXT_BACKEND_SHARED_SECRET` и `NUXT_BACKEND_INSTANCE_ID`.
Для каждого вуза Nitro использует свой API, профиль, базу знаний и только
токены ботов этого вуза. Подробности клиентской настройки находятся в Mini App.
Без настроенных идентификатора и секрета маршруты чата возвращают 503.

Nitro проверяет подписанные данные запуска своим токеном Telegram или MAX.
В API он передаёт краткоживущее утверждение HMAC с идентификатором экземпляра,
платформой и внешним ID. API использует для выборок всю эту тройку.
Серверная история и контекст хранятся в PostgreSQL. Лимиты учитывают запросы
Mini App и мессенджера для одной учётной записи платформы. Непрошедшие
проверку подлинности запросы не имеют доступа к пользовательскому API.
Оформление читается через публичный `GET /api/v1/branding`.

## Контракт

Маршруты под `/api/v1/mini-app/chats`.

| Метод и путь | Результат |
| --- | --- |
| `GET /` | Список диалогов владельца |
| `POST /` | Создаёт диалог по UUID, переданному Nitro |
| `GET /{chat_id}` | Сохранённые вопросы и ответы этого диалога |
| `POST /{chat_id}/turns` | Принимает UUID сообщения и текст вопроса |
| `PUT /{chat_id}/turns/{turn_id}/rating` | Сохраняет первую оценку и возвращает сохранённое значение |

Повтор отправляет тот же UUID и текст. Для завершённого сообщения API
возвращает сохранённый ответ, для неудачного запускает обработку вновь.
Одновременно обрабатывается один вопрос на диалог. Через 105 секунд
прерванную попытку можно повторить после перезапуска процесса или клиента.
Пайплайн получает только завершённые пары вопроса и ответа текущего диалога,
в пределах существующего окна контекста. Оценки поступают в действующий
процесс обработки обратной связи.

## Дальнейшие задачи

1. **Комментарий к ответу.** Добавить пользовательский маршрут для комментария
   к конкретному ответу и переиспользовать `FeedbackReportService`. Требуются
   проверка владельца, привязка к паре вопроса и ответа и решение о том, какой
   снимок контекста нужен редактору. Затем добавить форму и подтверждение в Mini App.
2. **Отслеживание позиции.** Уточнить, должен ли Mini App разделять подписку
   `User.applicant_id` с ботом или поддерживать независимый список направлений.
   Подготовить принадлежащие пользователю маршруты чтения позиции и управления
   подпиской поверх конкурсных списков и scheduler. Согласовать поведение
   уведомлений и сверить схему конкурсов с макетом «Мои заявления».
3. **Приёмка в клиентах.** Нужны отдельный HTTPS-стенд, подключённая база знаний
   вуза и тестовые боты Telegram и MAX. Проверить мобильные WebView, экранную
   клавиатуру, восстановление после сворачивания, источники и уведомления
   платформ в поддерживаемых клиентах.
