# Исследование технологий разбивки текста на чанки

## Введение

Для создания эффективной базы знаний (knowledge base) с использованием RAG (Retrieval-Augmented Generation) необходимо правильно разбить исходные документы на чанки (chunks) - небольшие фрагменты текста, по которым будут строиться эмбеддинги (векторные представления).

Качество разбивки на чанки критически важно для:
- **Точности поиска**: правильные границы чанков сохраняют семантическую целостность
- **Качества ответов**: LLM получает релевантный и полный контекст
- **Производительности**: оптимальный размер чанков влияет на скорость поиска и затраты

## Основные методы разбивки текста

### 1. Fixed-size chunking (Фиксированный размер)

**Описание**: Текст делится на чанки фиксированной длины (например, 512 токенов) с возможным перекрытием (overlap).

**Преимущества**:
- Простота реализации
- Предсказуемый размер чанков
- Быстрая обработка

**Недостатки**:
- Может разрывать логически связанные части текста
- Не учитывает структуру документа
- Может разрывать предложения посередине

**Когда использовать**: Для простых документов без сложной структуры, когда важна скорость обработки.

### 2. Recursive chunking (Рекурсивная разбивка)

**Описание**: Текст делится по естественным разделителям (параграфы, предложения, слова) с учетом иерархии.

**Преимущества**:
- Сохраняет структуру текста
- Гибкость в выборе разделителей
- Лучше сохраняет семантическую целостность

**Недостатки**:
- Более сложная реализация
- Менее предсказуемый размер чанков

**Когда использовать**: Для структурированных документов (статьи, документация).

### 3. Semantic chunking (Семантическая разбивка)

**Описание**: Использует эмбеддинги для определения семантических границ между частями текста.

**Преимущества**:
- Максимально сохраняет семантическую целостность
- Адаптируется к содержанию
- Лучшее качество для RAG

**Недостатки**:
- Вычислительно затратна (требует генерации эмбеддингов)
- Более медленная обработка
- Сложнее настроить

**Когда использовать**: Когда качество важнее скорости, для сложных документов.

### 4. Document-structure aware chunking

**Описание**: Учитывает структуру документа (заголовки, секции, таблицы, код).

**Преимущества**:
- Сохраняет контекст структурных элементов
- Идеально для технической документации
- Может добавлять метаданные (например, путь в иерархии заголовков)

**Недостатки**:
- Требует парсинга структуры
- Специфична для формата документа

**Когда использовать**: Для Markdown, HTML, документации с кодом.

## Обзор библиотек для разбивки на чанки

### 1. Chonkie

**Ссылки**:
- GitHub: https://github.com/bhavnicksm/chonkie
- Статья на Habr: https://habr.com/ru/companies/raft/articles/954158/

**Описание**: Современная Python библиотека, специально разработанная для эффективной разбивки текста на чанки для RAG-систем.

**Основные возможности**:
- **TokenChunker**: разбивка с учетом токенов (работает с любым токенизатором)
- **WordChunker**: разбивка по словам
- **SentenceChunker**: разбивка по предложениям
- **SemanticChunker**: интеллектуальная разбивка с использованием эмбеддингов
- **SDPMChunker**: Sequential Dependency Pattern Matching - учитывает зависимости в тексте
- Поддержка различных токенизаторов (HuggingFace, tiktoken)
- Настраиваемое перекрытие (overlap) чанков

**Преимущества**:
- Современная и активно развивающаяся библиотека
- Множество стратегий разбивки из коробки
- Хорошая интеграция с популярными LLM-библиотеками
- Оптимизирована для RAG
- Простой API
- Хорошая документация

**Недостатки**:
- Относительно новая библиотека (меньше production-опыта)
- Меньшее комьюнити по сравнению с LangChain

**Пример использования**:
```python
from chonkie import TokenChunker
from transformers import AutoTokenizer

# Инициализация
tokenizer = AutoTokenizer.from_pretrained("model-name")
chunker = TokenChunker(
    tokenizer=tokenizer,
    chunk_size=512,
    chunk_overlap=128
)

# Разбивка текста
chunks = chunker.chunk(text)
```

### 2. LangChain Text Splitters

**Ссылки**:
- Документация: https://python.langchain.com/docs/modules/data_connection/document_transformers/

**Описание**: Набор инструментов для разбивки текста в экосистеме LangChain.

**Основные splitters**:
- **CharacterTextSplitter**: базовая разбивка по символам
- **RecursiveCharacterTextSplitter**: рекурсивная разбивка (рекомендуется)
- **TokenTextSplitter**: разбивка с учетом токенов
- **MarkdownTextSplitter**: для Markdown документов
- **PythonCodeTextSplitter**: для Python кода
- **HTMLHeaderTextSplitter**: для HTML с учетом заголовков

**Преимущества**:
- Часть большой экосистемы LangChain
- Множество готовых splitters для разных форматов
- Большое комьюнити и много примеров
- Production-ready
- Хорошая интеграция с другими компонентами LangChain

**Недостатки**:
- Зависимость от всей библиотеки LangChain (heavyweight)
- Некоторые splitters могут быть избыточными для простых задач

**Пример использования**:
```python
from langchain.text_splitter import RecursiveCharacterTextSplitter

splitter = RecursiveCharacterTextSplitter(
    chunk_size=1000,
    chunk_overlap=200,
    separators=["\n\n", "\n", " ", ""]
)

chunks = splitter.split_text(text)
```

### 3. LlamaIndex Node Parsers

**Ссылки**:
- Документация: https://docs.llamaindex.ai/en/stable/module_guides/loading/node_parsers/

**Описание**: Инструменты для разбивки документов в экосистеме LlamaIndex.

**Основные parsers**:
- **SentenceSplitter**: разбивка по предложениям
- **TokenTextSplitter**: по токенам
- **SemanticSplitterNodeParser**: семантическая разбивка
- **MarkdownNodeParser**: для Markdown
- **HTMLNodeParser**: для HTML

**Преимущества**:
- Интеграция с LlamaIndex
- Хорошо подходит для создания индексов
- Автоматическое создание метаданных

**Недостатки**:
- Привязка к экосистеме LlamaIndex
- Менее гибкая, чем специализированные решения

### 4. Semantic-text-splitter

**Ссылки**:
- GitHub: https://github.com/benbrandt/text-splitter

**Описание**: Rust-библиотека с Python биндингами для быстрой разбивки текста.

**Преимущества**:
- Очень быстрая (написана на Rust)
- Поддержка множества языков
- Семантически осмысленная разбивка

**Недостатки**:
- Меньше возможностей настройки
- Менее популярна

### 5. Unstructured.io

**Ссылки**:
- GitHub: https://github.com/Unstructured-IO/unstructured
- Документация: https://unstructured-io.github.io/unstructured/

**Описание**: Комплексное решение для обработки неструктурированных данных.

**Преимущества**:
- Поддержка множества форматов (PDF, DOCX, HTML, и др.)
- Извлечение структуры из документов
- Готовые решения для chunking

**Недостатки**:
- Тяжеловесное решение
- Может быть избыточным для простых задач

## Рекомендации для проекта abitur-bot

### Контекст проекта

Для телеграм-бота абитуриентов НГУ нужно обрабатывать:
- Информацию с сайта НГУ (HTML/текст)
- FAQ и документацию о поступлении
- Информацию об общежитиях, стипендиях, программах
- Возможно, PDF документы и файлы

### Рекомендуемое решение: **Chonkie**

**Обоснование выбора**:

1. **Специализация на RAG**: Библиотека создана специально для RAG-систем, что идеально подходит для нашей задачи.

2. **Простота использования**: Минимальный boilerplate код, простой API - можно быстро начать работу.

3. **Гибкость стратегий**: Возможность экспериментировать с разными методами разбивки:
   - Начать с `TokenChunker` для быстрого прототипа
   - Перейти на `SemanticChunker` для улучшения качества
   - Использовать `SentenceChunker` для структурированных FAQ

4. **Независимость**: Не привязывает к тяжелым фреймворкам (LangChain/LlamaIndex), что дает свободу в выборе других компонентов системы.

5. **Современность**: Активная разработка, учитывает последние практики в области RAG.

6. **Поддержка русского языка**: Работает с различными токенизаторами, включая поддерживающие русский язык.

### Альтернативный вариант: **LangChain RecursiveCharacterTextSplitter**

Если в будущем планируется использовать другие компоненты LangChain:
- Уже есть в экосистеме
- Проверено временем
- Много примеров и документации

### Предложенная стратегия разбивки

1. **Начальный этап** (MVP):
   - Использовать `TokenChunker` от Chonkie
   - Размер чанка: 512 токенов
   - Overlap: 50-100 токенов
   - Причина: простота, быстрый старт

2. **Улучшение качества**:
   - Переход на `SemanticChunker`
   - Экспериментирование с размерами чанков
   - A/B тестирование качества ответов

3. **Для структурированных данных** (FAQ):
   - `SentenceChunker` или разбивка по логическим блокам
   - Каждый вопрос-ответ = отдельный чанк

### Пример конфигурации

```python
from chonkie import TokenChunker
from transformers import AutoTokenizer

# Для русского языка можно использовать
tokenizer = AutoTokenizer.from_pretrained("cointegrated/rubert-tiny2")

chunker = TokenChunker(
    tokenizer=tokenizer,
    chunk_size=512,        # оптимально для большинства embedding моделей
    chunk_overlap=100      # достаточное перекрытие для контекста
)

# Обработка документа
chunks = chunker.chunk(document_text)

# Каждый чанк можно дополнить метаданными
for i, chunk in enumerate(chunks):
    chunk_with_metadata = {
        "text": chunk.text,
        "chunk_id": i,
        "source": document_url,
        "category": "admission_info"  # например
    }
```

## Дополнительные рекомендации

### Размер чанков

- **Для коротких ответов** (FAQ): 256-512 токенов
- **Для подробной информации**: 512-1024 токенов
- **Общая рекомендация**: начать с 512 и экспериментировать

### Overlap (перекрытие)

- **Минимальное**: 10-15% от размера чанка
- **Рекомендуемое**: 20-25% (100-128 токенов для чанка в 512 токенов)
- **Причина**: сохранение контекста на границах чанков

### Метаданные

Важно сохранять метаданные для каждого чанка:
- URL источника
- Дата обновления
- Категория информации (поступление, общежитие, стипендии, etc.)
- Заголовок раздела
- Позиция в документе

### Предобработка текста

Перед разбивкой на чанки:
1. Удалить ненужные HTML теги
2. Нормализовать пробелы и переносы строк
3. Удалить навигационные элементы
4. Сохранить важную структуру (заголовки, списки)

## Заключение

Для проекта abitur-bot **рекомендуется использовать библиотеку Chonkie** с начальной стратегией `TokenChunker` и последующим переходом на `SemanticChunker` при необходимости улучшения качества.

Эта библиотека предоставляет оптимальный баланс между простотой использования, гибкостью и качеством для задачи создания базы знаний RAG-системы.

### Следующие шаги

1. Установить Chonkie: `pip install chonkie`
2. Выбрать токенизатор с поддержкой русского языка
3. Создать прототип с `TokenChunker`
4. Собрать тестовый набор документов
5. Экспериментировать с параметрами (chunk_size, overlap)
6. Оценить качество поиска и ответов
7. При необходимости попробовать `SemanticChunker`
