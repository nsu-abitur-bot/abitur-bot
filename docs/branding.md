# Оформление экземпляра

Задача: nsu-abitur-bot/abitur-web#45. Промпты и правила ответа не меняются.
В панели superadmin: Подключения → Оформление вуза. Один логотип применяется
к навигации и вкладке браузера; названия и один HEX-цвет имеют локальный
предпросмотр. Сохранить применяет весь черновик; отмена загружает серверную версию.
При 409 загрузить новую версию, сверить сохранённый черновик и сохранить повторно.
Технический профиль nsu/custom находится отдельно; сайт, контакты и ASSISTANT_NAME
не удалены из API/хранилища и не представлены как оформление/имя мессенджер-бота.

## Контракт (API выкладывается первым)

- `GET /api/v1/branding`: публичный whitelist `revision`, `short_name`,
  `full_name`, `logo_url`, `favicon_url`, `accent_color`. `Cache-Control: no-store`.
  Не возвращает профиль подключения, секреты, контакты или описание роли.
- Существующие `GET /university`, `GET /university/profile`,
  `GET/PUT /settings/instance` совместимы. Новый ключ `UNIVERSITY_ACCENT_COLOR`
  имеет default `#4b4bd2`, принимает ровно `#RRGGBB`.
- `POST /api/v1/settings/instance/branding`: multipart `revision` (int),
  `changes` (JSON объект того же контракта, что PUT), необязательный `logo`
  (один файл) или `remove_logo=true`. Ответ — `InstanceSettingsResponse`.
  Superadmin проверяется на каждом запросе; 409 сохраняет рабочее оформление.
  400 — повреждённый/слишком большой файл, размеры или поля; 503 — хранилище.
  Запрос объединяет правки полей и логотипа в одну ревизию. При сетевом обрыве
  после отправки сначала получить актуальную версию: сервер мог успеть сохранить.
- Файл проверяется по содержимому (PNG/WebP/JPEG, один кадр), до 2 MiB,
  стороны 1–4096, до 8 миллионов пикселей до полного decode. Входное имя/MIME
  не задают формат или путь. Pillow перекодирует растр в PNG без метаданных;
  отдельно автоматически готовится прозрачный 64×64 PNG с отступами.
- Относительные URL `/api/v1/branding/media/<uuid>.png` и `<uuid>-icon.png`
  разрешаются относительно API origin, включая SSR. Никаких загрузок внешних
  URL сервером нет. Старые HTTP(S) UNIVERSITY_LOGO_URL продолжают отображаться;
  для автоматической иконки старый логотип нужно один раз загрузить файлом.
  Без подготовленной иконки используется стандартный значок проекта.
- Media GET публичный, только UUID PNG; `nosniff`, CSP sandbox, immutable cache.
  Каждая замена получает новый URL. Удаление возвращает пустые media URL.
  Старые файлы намеренно сохраняются: открытые вкладки и конкурентные запросы
  не теряют ресурс; удаление из формы снимает ссылку, не гарантирует стирание
  публичного файла/кэша. Не загружайте конфиденциальные материалы.
  Неудавшийся запрос убирает только собственные новые файлы, никогда рабочие.

## Постоянное хранилище и выкладка

`BRANDING_MEDIA_DIR` — серверный каталог (локально default `./branding-media`,
в compose `/app/branding-media`). Он исключён из git и Docker build context.
Корневой compose монтирует отдельный named volume `branding_media`, demo compose
— `branding` с префиксом INSTANCE_NAME. Все API workers одного экземпляра должны
видеть один том; разные экземпляры — разные тома. Нужен UID/GID 1000 на каталоге;
Dockerfile создаёт mountpoint с владельцем app, demo permissions обслуживает его.
Внешнему reverse proxy задайте разумный предел request body (например 3 MiB).
Файл в UploadFile ограничивается приложением, но multipart сначала принимает ASGI.

Порядок действий владельца deployment (этот PR ничего не выкладывает):

1. Сделать резервную копию БД и создать/подключить отдельный постоянный media-том
   с правами app. Не использовать image filesystem, общую папку другого вуза
   или `docker compose down -v`. Бэкапить БД и media-том согласованно.
2. Выложить backend PR; миграция схемы БД не требуется. Проверить публичный
   `/api/v1/branding` и существующие endpoints. Сохранить том при смене image.
3. Выложить frontend PR с актуальным OpenAPI, проверить API origin/CORS и
   доступность `/api/v1/branding/media/*` из браузера. Путь не требует токена.
4. Для настоящего nsu.abitur.site основной агент берёт официальный логотип НГУ
   и фирменный акцент из официального источника (не из QA-фикстуры). Superadmin
   вводит краткое/полное названия, один логотип, акцент; сверяет preview и Save.
   Профиль nsu проверяет отдельно; подключения моделей/ботов не меняет, MAX
   не включает. Промпты/контакты не редактирует.
5. Проверить login и админку, светлую/тёмную тему, мобильную навигацию, reload,
   реальный head favicon URL и PNG. Замена/удаление должны обновить оба применения.

Откат frontend совместим с новым API. Откат API к версии без media endpoint
требует оставить media route на proxy либо предварительно вернуть legacy URL
через штатные настройки. Том и БД при откате не удалять.
