# Программы СПО в справочнике

Поддержка добавлена в рамках [#419](https://github.com/nsu-abitur-bot/abitur-bot/issues/419).

Раздел «Факультеты» хранит подразделения университета, включая колледжи.
Программа относится к подразделению и имеет название, уровень образования,
необязательный код специальности и признак активности. Для СПО используется
канонический уровень `spo`, в интерфейсе — «СПО». Существующие уровни
`bachelor`, `specialist`, `master` сохраняют значения и поведение.

## API и хранение

`POST /api/v1/faculties/{faculty_id}/programs` создаёт программу с `level: "spo"`.
`PUT /api/v1/faculties/programs/{program_id}` позволяет изменить уровень;
пропущенное поле сохраняет прежнее значение. Ответы API и список факультетов
возвращают сохранённый уровень. Допустимые уровни перечислены в OpenAPI.

Миграция не требуется: `program.level` уже имеет тип `VARCHAR(20)`, без SQL enum
или CHECK-ограничения на прежние три значения. Изменяется только Python-справочник
допустимых значений. Уникальность `(faculty_id, name, level)` уже позволяет
одноимённые программы разных уровней. Значение по умолчанию `bachelor` не меняется;
существующие записи и их уровни не переписываются.

## Поиск и инструменты бота

CRAG распознаёт «СПО» как отдельное слово и полную формулировку «среднее
профессиональное образование». При заданном уровне авторитетная фильтрация
исключает направления других уровней и предложения с явным другим уровнем,
сохраняя общий контекст. Одинаковое название само по себе не доказывает уровень.

`get_education_programs` читает активные программы из справочника с фильтрами
`faculty` и `level`. Каждая строка содержит название, код при наличии,
подразделение и уровень. Для вопроса о СПО инструмент вызывается с `level="spo"`.
`get_admission_scores` также принимает `level`; повторный поиск по доступным
годам сохраняет этот фильтр. Результаты с баллами содержат уровень программы.

Системный промпт не менялся. Автотесты проверяют контракт инструментов и
фильтрацию, но выбор инструмента живой моделью требует продуктовой приёмки.

## Сценарий приёмки

Синтетические данные ниже нужны для проверки поведения, а не описывают
реальные программы или условия приёма НГУ.

1. В разделе «Факультеты» создать подразделение «Колледж университета».
2. Добавить «Информационные системы и программирование», код `09.02.07`,
   уровень «СПО». Закрыть форму, обновить страницу, открыть редактирование:
   название, код и «СПО» должны сохраниться.
3. Изменить название, сохранить, снова обновить страницу и открыть форму.
   Уровень должен остаться «СПО».
4. Добавить к этому же подразделению одноимённые контрольные программы
   бакалавриата, специалитета и магистратуры с отличающимися кодами.
5. Спросить бота: «Какие программы СПО есть в колледже университета?»
   Ожидание: чтение справочника через `get_education_programs` с `level="spo"`,
   ответ с программой СПО и её кодом, без контрольных программ высшего образования.
6. Повторить вопрос с полной формулировкой «среднее профессиональное
   образование», затем отдельно спросить о бакалавриате, специалитете и
   магистратуре. Для каждого уровня должны возвращаться только его записи.
7. При отсутствии записей СПО бот сообщает об отсутствии данных справочника,
   не подменяя их программами высшего образования.

Покрытие: тесты faculty API и PostgreSQL проверяют запись и повторное чтение;
тесты CRAG и инструментов — разделение уровней; браузерный сценарий abitur-web —
создание, изменение и повторное открытие формы после перезагрузки.
