# Отдельные демостенды для вузов

Команда вручную создаёт отдельный Compose-проект на вуз из одного checkout.
Конфигурация: `deploy/demo/compose.yaml`. Рядом с backend должен быть checkout
`abitur-web` (ветка с настройками экземпляра #356). UI собирается его существующим
Dockerfile; менять исходники UI для каждого вуза не нужно.

## Сервер и параметры

Нужны Git, Docker Engine с Compose v2+ и uv для подготовки env/проверки.
Для двух малонагруженных демо начальный ориентир — 4 vCPU, 8 GiB RAM,
30 GiB свободного SSD; сборка Python/эмбеддингов может требовать больше памяти и
диска. Это бюджет для старта, не результат нагрузочного теста. Серверу нужен
выход к реестрам образов, пакетным репозиториям и выбранным LLM-провайдерам.

Каждый env содержит только инфраструктуру и корневые секреты:

| Параметр | Значение |
| --- | --- |
| INSTANCE_NAME | Уникальное неизменяемое имя Compose-проекта |
| API_PORT / WEB_PORT | Два свободных порта, уникальные на машине |
| BIND_ADDRESS | По умолчанию 127.0.0.1; адрес интерфейса для публикации |
| API_ORIGIN | Адрес API, доступный **браузеру пользователя** |
| WEB_ORIGIN | Адрес UI, доступный браузеру; единственный CORS origin API |
| WEB_SOURCE | Путь к checkout abitur-web, относительно compose.yaml; по умолчанию соседний репозиторий |
| DB_PASSWORD / REDIS_PASSWORD | Уникальные hex-пароли без URL-спецсимволов |
| SECRET_KEY | Уникальный ключ JWT |
| SETTINGS_ENCRYPTION_KEY | Уникальный Fernet-ключ секретов в БД |
| WEB_SESSION_PASSWORD | Уникальный корневой секрет UI |

Внутри каждого проекта адреса одинаковые (`postgres:5432`, `redis:6379`,
`api:8000`), но сети раздельные. Имя `api` не подходит для API_ORIGIN: запросы
из UI выполняет браузер, а не контейнер. Файлы и LightRAG находятся в volume
`<INSTANCE_NAME>_files` под `/app/data`, логи — в `<INSTANCE_NAME>_logs`.
PostgreSQL и Redis имеют собственные volumes. Нет фиксированных container_name,
внешней общей сети, общих bind mounts или опубликованных портов баз данных.
Одинаковые имена таблиц и graph_id безопасны благодаря отдельным хранилищам.

## Создание двух экземпляров

Все команды ниже — из корня backend. Секретные файлы держите вне checkout,
резервируйте отдельно от БД, не передавайте в логи/issue. Генератор создаёт файл
с правами 0600 и отказывается перезаписывать существующий.

```bash
git clone https://github.com/nsu-abitur-bot/abitur-web.git ../abitur-web
mkdir -p /tmp/abitur-demo
uv run python deploy/demo/create_env.py /tmp/abitur-demo/a.env demo-a --api-port 18001 --web-port 13001
uv run python deploy/demo/create_env.py /tmp/abitur-demo/b.env demo-b --api-port 18002 --web-port 13002

docker compose --env-file /tmp/abitur-demo/a.env -f deploy/demo/compose.yaml up -d --build
docker compose --env-file /tmp/abitur-demo/b.env -f deploy/demo/compose.yaml up -d --build
```

`/tmp` пригоден только для локальной проверки. На сервере храните env постоянно,
например `/etc/abitur-instances/a.env`, с ограниченным доступом. Не задавайте
`COMPOSE_PROJECT_NAME`/`-p` поверх INSTANCE_NAME: изменение имени создаёт другие
volumes. Корневой `.env` backend не передаётся контейнерам; Docker build также
исключает его. Пользователь API работает с UID 1000; одноразовый permissions
подготавливает права только корней volumes. migrate выполняет Alembic до API,
не запускает сиды НГУ, парсеры, polling или планировщик.

Первого superadmin создайте локально в каждом экземпляре после миграций:

```bash
docker compose --env-file /tmp/abitur-demo/a.env -f deploy/demo/compose.yaml exec api uv run python -m api.auth.bootstrap --username admin
docker compose --env-file /tmp/abitur-demo/b.env -f deploy/demo/compose.yaml exec api uv run python -m api.auth.bootstrap --username admin
```

Команды требуют интерактивного терминала: пароль вводится скрыто дважды.
Не передавайте пароль в аргументах, shell history или логах. Bootstrap работает
только при пустой таблице admins, повторный запуск отказывает и не меняет пароли.
Для запуска из checkout: `uv run python -m api.auth.bootstrap --username admin`
с настройками БД нужного экземпляра; подробнее [admin-auth.md](admin-auth.md).

Откройте http://localhost:13001 и http://localhost:13002 и войдите созданными
аккаунтами. HTTP-регистрация всегда требует действующий одноразовый инвайт,
включая пустую БД. Остальных приглашайте через админку. Имена, пароли и JWT
не переносятся между экземплярами.

После входа откройте «Настройки системы → Настройки экземпляра»: задайте LLM,
эмбеддинги и PDF-парсер, проверьте подключения; затем загрузите свои материалы.
LLM-ключи, Telegram/MAX-токены и прикладные параметры в env не добавляйте.
Подробности: [настройки экземпляра](instance-settings.md). Изменение эмбеддингов
после наполнения индекса требует отдельной процедуры миграции.
Не включайте сиды НГУ для чужого вуза. Ограничения промптов и адаптация источников
другого вуза остаются в #357, приёмка пилота — #359.

Веб-демо работает без токенов мессенджеров: запущены только API/UI и хранилища.
Запуск живого диалога в Telegram/MAX потребует отдельного процесса bot и токена
именно этого вуза; включение канала в панели само по себе не запускает отсутствующий
процесс. Планировщик в демоконфигурацию намеренно не входит.

Для внешнего размещения задайте реальные WEB_ORIGIN/API_ORIGIN и настройте
HTTPS reverse proxy перед localhost-портами; браузеру должны быть доступны оба
адреса. Для разных вузов используйте разные домены UI/API. Разные порты одного
localhost разделяют localStorage, но cookie не изолируются портами; session name
дополнительно содержит имя экземпляра. Не выдавайте клиентам Docker/SSH-доступ
к машине с чужими экземплярами.

## Обновление, перезапуск, остановка

Сохраните хеши обеих версий кода перед обновлением. Резервное копирование — #229;
здесь нет отдельной реализации backup. Для выбранного экземпляра:

```bash
git pull --ff-only
git -C ../abitur-web pull --ff-only
docker compose --env-file /tmp/abitur-demo/a.env -f deploy/demo/compose.yaml up -d --build --force-recreate
docker compose --env-file /tmp/abitur-demo/a.env -f deploy/demo/compose.yaml logs --tail 100 api migrate web
```

Миграции выполняются перед новым API; обновление не удаляет volumes и настройки.
Другой Compose-проект продолжает работать на прежних контейнерах. Миграции могут
менять схему: откат кода не заменяет восстановление совместимой БД из backup.
Текущие Dockerfile используются без введения публикации образов (#238).
Новые healthcheck приложения относятся к #241; используются существующие проверки
готовности PostgreSQL/Redis и порядок запуска, а не обещание готовности API/UI.

```bash
# Перезапуск выбранного экземпляра без обновления
docker compose --env-file /tmp/abitur-demo/a.env -f deploy/demo/compose.yaml restart api web postgres redis
# Остановка с сохранением данных и возможность повторного up
docker compose --env-file /tmp/abitur-demo/a.env -f deploy/demo/compose.yaml down
# Повторный запуск
docker compose --env-file /tmp/abitur-demo/a.env -f deploy/demo/compose.yaml up -d
```

Нельзя применять `down -v`, `volume prune` или удалять env при обычном обновлении.
`down -v` предназначен исключительно для сознательного удаления одноразового демо.

## Проверка изоляции до сервера

Только на двух **пустых одноразовых** стендах из примера, не на действующих
пилотах, **до ручного bootstrap**. Скрипт создаёт первые аккаунты локально
через сервис bootstrap, передавая случайный пароль через stdin процесса без
аргументов и логирования; для повторного прогона используйте
новые имена проектов и env:

```bash
uv run python deploy/demo/verify.py /tmp/abitur-demo/a.env /tmp/abitur-demo/b.env
```

Скрипт создаёт временные учётные записи, документ и историю через ORM настоящей
PostgreSQL первого экземпляра, а также маркеры Redis, файлов LightRAG и логов.
Проверяет UI, вход через API, отказ JWT/пароля первого стенда во втором,
отсутствие документа/истории/файлов во втором. Затем перезапускает, пересоздаёт
контейнеры (путь обновления) и останавливает первый проект, проверяет сохранение
данных и неизменность ID API второго проекта. В конце первый запускается снова.
Фикстура документа не вызывает платные LLM и не проверяет качество индексации.
Дополнительно через панель с собственными ключами проверьте загрузку реального
документа и невозможность найти его из другого стенда.

Отчёт локальной проверки: [demo-validation.md](demo-validation.md).
