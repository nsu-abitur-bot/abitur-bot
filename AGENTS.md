# AGENTS.md

Карта проекта для AI-агентов. Это **канонический источник** правил (на него
ссылается CLAUDE.md).

Здесь только то, что нужно почти в любой задаче. Подробности — в разделах ниже,
**открывай их по надобности, а не все сразу**: контекст конечен, и справочник в
нём вытесняет код и задачу.

## Проект

**NSU Abitur Bot** — Telegram/MAX-бот для абитуриентов Новосибирского
государственного университета. Отвечает на вопросы о поступлении и о том, что
происходит сразу после него.

Ответ собирается слоями, от дешёвого к дорогому: расширение аббревиатур →
FAQ-матчер (при попадании отвечает сразу) → поиск по базе знаний (Corrective RAG
поверх LightRAG) → генерация модели с доступом к function-calling инструментам.
Точка входа — `pipeline/llm_client.py:ask_local_llm`.

Три независимых процесса: `main.py` (бот), `api/main.py` (FastAPI для админки),
`scheduler/main.py` (конкурсные списки и уведомления).

## Окружение

Менеджер зависимостей — **uv**. Никогда не используй `pip` или голый `python`.

```bash
uv run <command>     # запуск любой команды в venv проекта
uv add <package>     # добавить зависимость
uv sync              # синхронизировать окружение после изменения pyproject.toml
```

## Команды на каждый день

```bash
# Запуск
uv run python main.py
uv run uvicorn api.main:app --reload --port 8000
uv run python -m scheduler.main

# Проверки — прогоняй после изменений, а не только перед коммитом
uv run pytest
uv run ruff check .
uv run pyrefly check
```

## Соглашения по коду

- **Нейминг**: `snake_case` везде — файлы, переменные, функции, модули.
- **Импорты**: абсолютные везде, кроме `db/postgres/services/` — там относительные.
- **Типизация**: аннотации обязательны для публичных функций.
- **Комментарии**: только когда неочевидно «почему», не «что делает».
- **Форматирование**: `ruff format` только по изменённым файлам, не по всему репозиторию.
- **Тесты**: реальная тестовая база вместо моков, и никакой зависимости от файлов вне git — см. [тесты](docs/agents/testing.md).
- **Зависимости между пакетами**: только вниз по слоям. Проверяется в CI (`uv run python tools/check_layers.py`) — см. [слои и зависимости](docs/agents/structure.md#слои-и-зависимости).

## Правила разработки

- **Починка бага начинается с падающего теста.** Тест, который падает до правки
  и проходит после, — единственное доказательство, что причина найдена там, где
  её искали.
- **Изменение поведения ответа приходит со сценарием в эталонном наборе.** Иначе
  итерация не накапливается: проверили руками один раз и забыли. Каркас набора
  переделывается в #305, до этого — хотя бы описанный сценарий в задаче.
- **Промпты и правила ответа — продуктовая логика**, а не «просто строки».
  Правки в них обсуждаются, а не вносятся по ходу. Тексты промптов пайплайна —
  в `pipeline/prompts.py`, с версией у каждого.

## Где какая документация живёт

**Репозиторий** (`AGENTS.md` и `docs/agents/`) — повседневная работа над кодом:
как устроен код, как его запускать и проверять, какие соглашения соблюдать.
Меняется вместе с кодом, в том же пулл-реквесте.

**Вики** — документы курса: Vision, SAD, требования, план релиза, таблица
рисков, график. Описывают задачу и обязательства, а не устройство кода. Живут
отдельным репозиторием, правятся отдельно.

Если сомневаешься: правило, которое нужно знать, чтобы не сломать код, —
в репозиторий; решение или обязательство перед курсом — в вики.
